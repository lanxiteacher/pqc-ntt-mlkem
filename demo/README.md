## 其余三页各是什么

| 页 | 内容 | 一句话 |
|---|---|---|
| `index.html` | 正变换 7 步 | CT/DIT 蝶形，len 从 128 递减到 2，k 从 1 递增 |
| `intt.html` | 逆变换 7 步 + 末级缩放 | GS/DIF 蝶形，len 从 2 递增到 128，k 从 127 递减 |
| `compare.html` | RTL 落盘输出 vs 黄金向量 | 4096 个系数逐比特，可点开看每一个 |

**正逆是对称的，而且共用同一张 `zetas[]` 表**（不存在 `zetas_inv`）：

```
正  组数 1 → 64   zetas[1]  → [127]   递增
逆  组数 64 → 1   zetas[127] → [1]    递减
```

页面上的 twiddle 范围就是照这个显示的，一路按下去能直接看出镜像关系。

## 数值口径与自检

### 变换页

- **口径**：每层都做 `canonical mod q` 归一化，落回 **0..3328**
  （与 `../refsim/ntt_ref_tool.c` 的输出口径一致）
- **自检判据（硬）**：正变换末级必须**逐值等于** `../research/mlkem_kat/ntt_out.hex`，
  逆变换末级必须**逐值等于** `../research/mlkem_kat/intt_out.hex`。
  脚本任一不过就非零退出、不写产物。

  | | 结果 |
  |---|---|
  | 正变换 | **16/16 组逐值一致**（4096 个系数） |
  | 逆变换 | **16/16 组逐值一致**（4096 个系数） |
  | 非退化 | 正变换输入 2355 个不同值；逆变换输入 2374 个不同值 |

- **页面自检**：页面自己按它**写出来的算式**把显示的数复算一遍，结果印在右下角
  「数据从哪来」栏里（正变换 28672 个值、逆变换 32768 个值，**都是 0 处不符**）。

### ⚠️ 蝶形算式必须写 `fqmul`，不能写成普通乘法

页面上写的是：

```
正  t = fqmul(zeta, b)        a′ = a + t          b′ = a − t
逆  t = a                     a′ = a + b          b′ = fqmul(zeta, b − t)
逆末级                        r′ = fqmul(r, 1441)  ≡ r × 512
```

`fqmul` 是 **Montgomery 乘**，自带 **R⁻¹ = 169** 的因子；表里的 `zeta` 本身又是
Montgomery 域的值（`zetas[0] = 2285 = R`）。两个因子正好抵消，真实的 twiddle 乘法
在 `fqmul` 之后才成立。**所以 `t` 不等于普通的 `zeta × b`。**

> **2026-09-29 更正**：本文件与旧版页面上原来写的是 `t = zeta × b` —— **那是错的**。
> 按那个式子算，本 README 里举的例子会得 3294，而页面同时显示的 a′/b′ 对应的是
> **t = 743**，页面自身对不上。已改成 `fqmul` 并加了这个说明框。
> 顺带一个能验的常数：逆变换末级 `fqmul(r, 1441)` 恰好等价于 `r × 512`，
> 而 512 = R/128 —— 这一步就是把 Montgomery 因子 R 引进来的那一步（tomont）。
> 举一反三：`../refsim/README.md` §七 说 RTL 的 INTT 输出与参考实现差 R⁻¹，
> 就是同一个因子在两端的不同位置。

> 生成器里对 `int16` 的截断是**显式**做的（`i16()`），乘法用 `Math.imul` 保证 32 位不溢出
> —— 否则与 C 的 `int16_t` 语义不一致，末级就对不上。改脚本时别动这两处。

### 对拍页

- **比的是**：`../refsim/batch/fntt_rtl_out.txt`（RTL 仿真真正落盘的值，
  由 `fntt_batch_tb_dump.v +dump=1` 写出）↔ `../research/mlkem_kat/ntt_out.hex`
- **结果**：**4096 / 4096 全中**（16 组 × 256），生成器每次重跑都会重新比一遍
- **非退化统计**：9 个 batch 文件的不同值 / 最常见占比，与
  `../refsim/README.md` §三 的表**逐格核对**，对不上就非零退出

  「演示：改坏一条期望值」按钮，能直观看到 1 个红格；另外生成器核过
  `fullmul_exp.txt` 第 1892 行原本就是 `3d4`，与那条记录自洽。

## 浅色主题（`?theme=light`）

各页默认**深色**；URL 加 `?theme=light` 即切**浅底**（报告要黑白可读）：

```
demo/index.html?theme=light
```

主题只覆盖 `ntt-view.js` 里那一组 CSS 变量（`:root[data-theme="light"]`），
**布局一个字都不改** —— 所以深浅两版不会各写各的。
颜色一律走变量，页面里**不再有硬编码颜色**（改色只改那一组变量）。

生成器 `gen_shots.mjs` 就是靠这个参数同时产出深色原图与浅色报告版。

## 截图（`gen_shots.mjs`）

本机没有 GUI 可供手动截图，所以截图也走**无头 Edge**：起调试端口 → CDP 点按钮
走到指定的那一层 → 截图 → 存两个去处：

| 去处 | 主题 | 命名 | 用途 |
|---|---|---|---|
| `../assets/` | 深色 | `YYYY-MM-DD_C_<一句话>.png` | 素材时间线（`assets/README.md` 的口径） |
| `../report/figures/` | 浅色 | `demo_*.png`（英文小写下划线） | 进报告的那一版（`figures/README.md` 的口径） |

```bash
node demo/gen_shots.mjs
```

⚠️ 只截「初始状态」不需要这套 —— `msedge --headless --screenshot` 就够了。
要截**走到第 N 层**的状态才必须驱动点击（键盘/按钮都能触发，脚本点的是 `#next`）。

脚本里 `SHOTS` 表决定截哪几张。每条可带这些字段：

- `page` / `next`（点几次下一步）/ `cell`（点第几个格子，-1 = 不点）/ `btn`（点哪个按钮 id）
- `theme`：`dark` 或 `light`；`out`：`assets` 或 `figures`
- `clip`（可选）：CSS 选择器，只截「从左上到该元素右下」的一块 ——
  **报告版用它**，否则对拍页整页又瘦又长（2880×3614）
- `expectBad`（可选）：截图前断言 `#grid` 里红格数，不符就退非零。
  **对拍页用**：pass 断言 0、negctrl 断言 1 —— 红格数**数出来**，不靠目视

`EDGE=<路径>` 可覆盖自动查找。
