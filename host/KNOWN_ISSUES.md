### D9 2026-10-07 第六轮 —— 拆开「发几行 / 收几行」（A 在真板子上撞出的 `#PMUL` 错位）

- **触发**：`logs/letter_2026-10-07_A_to_B_pmul_desync.txt`。真板子跑 `#PMUL NTT 1` 整轮被判错位停掉，
  陪练上同样复现 ⇒ 是**上位机**的账，不是 RTL 的账。A 定位到 `host.py:443`，并指出 `:316` 同源。
- **病根**：`Transaction` 身上只有**一个** `count`，同时兼两件事 ——「我要发几行」和「我要收几行」。
  `#NTT 1` 恰好 256 进 256 出，两个意思碰巧相等，所以这个 bug 从 W2 一直没露头；
  `#PMUL NTT 1` 是 **512 进 / 256 出**，板子回 `#BEGIN PMUL NTT 1 256`，
  老代码拿 256 去比「我发了 512」，判错位。
  依据是冻结文档 **§5.2:287**：`#BEGIN <原命令> <count>` 的 count = **即将发出的数据行数**；`:288` `#DONE`「同上」。
- **改法**（四个文件）：
  - `host/src/host.py`：`Transaction.count` → **`sent`**（我发几行，调用方给）＋ **`recv`**（板子说回几行，
    由 `#BEGIN` 填）；`run()` 收结果改按 `txn.recv`；`_wait_for()` 里 `#BEGIN` **只记录**（唯一权威），
    `#DONE` 改为与 `#BEGIN` **自洽**核对（不再和自己发了多少行比）。
  - `host/src/host.py` 另加**可选** `run(..., expect_rows=None)`：给了就多一道**独立**核对，
    板子自报的 `recv` != `expect_rows` → STOP。**为什么必须有它**：把发/收拆开后，
    `#BEGIN` 成了唯一权威 —— 板子若报一个「自己前后自洽（BEGIN==DONE）但整体是错的」数，
    没有第二个人核对，**改前会响亮停下、改后会静默判成功**。`expect_rows` 就是把那份核对补回来。
