## 二、执行阶段

### Phase 1 · 口径与叙事（不需要板子，10/22 前）

- [x] **1.1 §3.10.3 改成“分档比 CPU”**（文件：`report/design/03_performance_and_resources.md`）
  - 现状：只拿 pe1 18.08 µs 对 CPU ~4 µs，得出“目标不是单发延迟打赢 CPU”。
  - 改成：一张三档表 —— 延迟（µs）、吞吐（NTT/s）、对 CPU 的倍数；结论句改为
    “**pe1 慢 4–5×、pe4 相当、pe16 板上快 2.4–3.7×**；pe16@154MHz 的 0.45 µs 是推算，不混入”。
  - 判据：报告里不再出现无条件的“打不过 CPU”；每个倍数都能从 50/62.5/75/80 MHz 与周期数复算。
- [x] **1.2 封面加“三口径”小框**（文件：`00_front_matter.md`）
  - 内容：板上实跑 50 / 80 / 75 / 62.5 MHz；核推算 Fmax 168/160/154（**非实测**）；
    “6/6 = 5 条计算 + 1 条探活”；“8× 是线上时间，墙钟 3.2×”。
  - 判据：只看封面/摘要的人不会把 168 当板上频率。
- [x] **1.3 §3.10.5 加“能量/NTT”**（文件：`03_performance_and_resources.md`）
  - 表：三档 × {50 MHz, 提频} 的**总能量**与**动态能量**（= 功耗 × 延迟），单位 µJ。
  - 对照：CPU 按 45 W TDP 假设 × 4.05 µs ≈ 182 µJ（**明确标注是假设**），
    结论写“**约两个数量级**”，不写精确倍数。
  - 判据：每个数可由 §3.10.5 的功耗表 × §3.10.3 的延迟复算。
- [x] **1.4 README 加“板级与演示”一节**（文件：`README.md`）
  - 5 条命令：`run_board_prog.sh` / `run_board_txn_report.sh` / `run_board_freq_sweep.sh` /
    `run_board_power.sh` / `run_kem_trace_boards.sh`；再给 `board_run.py --baud 921600` 一句。
  - 判据：新人只看 README 能找到全部板级入口。
- [x] **1.5 “6/6”定义**（文件：`00_front_matter.md`、`03` §3.10.2）
  - 第一次出现处加括号“（5 条计算 + 1 条 `#PING` 探活）”。
- [x] **1.6 hold 余量说明**（文件：`03` §3.10.2）

### Phase 3 · 板级浸泡（A，需板子，10/21 晚已开跑）

- [ ] **3.1 连续 30–60 分钟 `#NTT`**（≥500 次事务）
  - **无间隔**：~500 次时 host 的 CH340 `write/flush` 永久阻塞（kill 后 `#PING` 正常）—— host/USB 层。
  - **20–50 ms 间隔**：仍在 ~100、~600 次复现；根因是 `SerialLink.write()` 的 `flush()` 无超时。
  - **`--no-flush` + 写超时 + 60 s 看门狗**：5 分钟 **1,152/1,152**、10 分钟 **2,062/2,062** 全过。
  - **40 分钟正式跑进行中**（no-flush，gap 20 ms），输出 `logs/verification_2026-10-21_A_soak.txt`；
    判据：0 超时/0 不符/0 异常。
