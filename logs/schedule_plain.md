## 〇、先花 3 分钟看懂我们在做什么

### 为什么要做这个

现在网上银行、微信、HTTPS 用的加密，安全性建立在"这道数学题太难算了，算不出来"上面。
但**量子计算机一旦造出来，这些题就变得好算了**。所以全世界在换一套新的加密算法，叫**后量子密码**。

美国国家标准局（NIST）定了其中一个标准叫 **ML-KEM**，用来在网络上安全地交换密钥。
ML-KEM 里面**最费时间的一步**，是一个叫 **NTT** 的数学变换。

**我们要做的**：做一块 FPGA 芯片，专门加速这一步，让它算得又快又省。

### NTT 是在算什么（打个比方）

拿 **256 个数字**，重新排列组合 **7 遍**：

- 每一遍，把所有数字**两两配对**
- 每一对做一次固定的运算（一加一减，再乘上一个事先算好的常数）——这个动作叫**蝶形**
- 做完 7 遍，得到另外 256 个数字

就这么简单。难点在于：ML-KEM 要反复做这件事很多次，软件做太慢，所以要用硬件（专门为这一件事造的电路）来加速。

### 我们的起点（重要）

**我们不是从零开始写。** 网上有一份别人写好、并且已经用官方考题验证过是正确的硬件设计，
放在 `research/ref_rtl/kyber-polmul-hw/pe1/`，我们叫它**基线**。

我们的工作 = **读懂基线 → 改造它 → 让它上板跑起来 → 把"它是对的"这件事证明给评委看**。

## 二、术语词典（看不懂的词都在这）

### A. 算法层

| 词 | 说人话 | 为什么要关心它 |
|---|---|---|
| **ML-KEM** | 美国定的后量子密码标准之一，用来安全地交换密钥 | 我们在给它做加速 |
| **NTT**（数论变换） | 把 256 个数字按固定规则重排组合 7 遍。每一遍两两配对做一次「蝶形」运算 | ML-KEM 里最耗时的步骤，我们的主攻对象 |
| **INTT**（逆变换） | NTT 的反向操作——把变过去的数字变回来。层序正好反着走 | 解密那一步要用 |
| **点乘**（basemul） | 两组各 256 个数字，一对一相乘 | 加密和解密都要用 |
| **蝶形**（butterfly） | 一对数字做「一加一减、再乘一个常数」这个固定动作 | 硬件里最小的工作单元。7 层 × 128 对 = 每遍 128 次蝶形 |
| **NTT 域** | 数字做过 NTT 之后所处的「状态」。点乘在这种状态下做才快 | 讨论「在哪个域做」时才需要提它 |
| **系数** | 就是那 256 个数字里的一个。干这行的人管它们叫「系数」 | 「4096 个系数逐位一致」= 16 组 × 256 个数字全对 |

### B. 硬件层

| 词 | 说人话 | 为什么要关心它 |
|---|---|---|
| **FPGA** | 一种「可以反复改电路的芯片」。写完设计下载进去，芯片就变成你要的电路 | 我们交付的硬件就是它 |
| **Verilog** | 一门描述电路长什么样的语言。注意：它写的**不是程序，是电路图** | A 要写的代码 |
| **RTL** | 就是「用 Verilog 写出来的电路设计」的统称。说「A 的 RTL」= A 写的那些电路代码 | 目录 `rtl/` 就是放这个的 |
| **Vivado** | AMD 的软件。干两件事：把 Verilog 变成芯片里的真电路；把结果下载到板子上 | A 的工位必须装它。已装好 |
| **综合** | Vivado 的第一步：把 Verilog 翻译成芯片里真实存在的零件（逻辑门、乘法器、内存块） | W3 要做 |
| **实现** | Vivado 的第二步：把这些零件摆到芯片的具体位置上、把线连起来 | W3 要做 |
| **时序收敛** | 检查「信号从这头跑到那头，来不来得及在 1 个时钟周期内跑完」。来不及叫**时序违例**，芯片会算错 | W3 要做。这是上板前必须过的关 |
| **XDC**（引脚约束） | 一张对照表，告诉 Vivado「电路里这个信号，接在芯片的第几号脚上」 | 写错了信号就跑到别的脚上，板子当然没反应。A 在 W3 写 |
| **bitstream**（比特流） | Vivado 折腾半天后吐出来的最终产物，一个 `.bit` 文件。下载进 FPGA，芯片就变成我们的电路 | 上板的最后一步。W4 |
| **LUT / DSP / BRAM** | 芯片里的三种资源。LUT＝通用小逻辑块，DSP＝专用乘法器，BRAM＝片上内存 | 用超了就装不进这颗芯片。这也是评分「性能与资源 20 分」要的数字 |
| **折叠度**（folding） | 「一次算几个蝶形」。一次算 1 个 → 省资源但慢；一次算 8 个 → 快但费资源 | 我们**创新性 30 分**的主要卖点：做成一个能调大小的旋钮 |

### C. 验证层

| 词 | 说人话 | 为什么要关心它 |
|---|---|---|
| **仿真** | 在电脑里假装自己是那块芯片，把电路跑起来看结果。**几秒钟出结果，不用插板子** | 绝大部分错误要在这一步抓出来 |
| **iverilog** | 我们用的免费仿真软件。装在 `C:\iverilog\bin`，**不在 PATH 里**，每次先 `export PATH="/c/iverilog/bin:$PATH"` | 跑仿真前必做 |
| **testbench**（测试台） | 一段专门用来「喂数据给电路、看它吐出来什么」的代码 | B 的主要工作 |
| **对拍** | 我们的硬件算一遍、标准 C 参考实现算一遍，两份结果**逐位比较**，全一样才算过 | 「验证通过」就是靠这个 |
| **黄金向量** | 一对文件：输入数据 + 标准答案。每行一个十六进制数 | 没有它就只能靠「看起来对」自测 |
| **KAT**（已知答案测试） | 官方出的考题——给输入、附标准答案。我们拿它对答案 | 「1000 条全过」说的就是这个 |
| **非退化** | 测试数据不能全是 0 或者只有几个数——那样「全对」很可能是**蒙对的** | 报告「通过」之前必须统计一下数据够不够五花八门 |
| **往返自检** | 正变换一遍再逆变换一遍，看能不能回到原来的数。**不需要标准答案，自己能证明自己** | 多一层保险 |
| **阴性对照** | 故意把答案改坏一个，看测试抓不抓得出来。抓不出来说明测试本身是坏的 | 证明「测试有效」 |
| **C 参考实现** | 官方用 C 语言写的标准版本，放在 `research/kyber_ref/`。它算的结果就是「标准答案」 | 对拍的对手 |

### D. 协作层

| 词 | 说人话 | 为什么要关心它 |
|---|---|---|
| **上位机** | 电脑上跑的那个程序。负责把数据通过串口线发给板子、把结果收回来、自动比对 | B 的工作 |
| **串口 / 串口号** | 电脑和板子之间那根数据线。**COM 口号会变**（Windows 按「插在哪个 USB 口」现分配），本机见过 COM10 和 COM9 —— 用前现查，别写死 | 板子在 A 的工位上 |
| **串口协议** | 两边约定好的「暗号本」——先发什么、后发什么、每个字节什么意思 | **不约定好，两边一定对不上**。原定 W2 必须冻结，✅ **09/29 已提前冻结 v1.0** |
| **联调** | 电脑程序 → 串口线 → 板子算 → 串口线 → 电脑程序，整条路真的通一遍 | W4 的「联调日」，B 到 A 的工位 |
| **交接点**（H1–H10） | 「你手上的东西，什么时候必须变成队友能用的东西」 | 见第四节。拖一条卡一线 |

## 六、卡住了怎么办

| 卡在哪 | 怎么办 |
|---|---|
| 拿不到 A 的端口说明 | 主动要。可以先照 `refsim/pe1/` 里已有模块的时序风格写个草稿 |
| 对拍不通过 | 先确认**比的是哪一个**：`poly_ntt()` 比裸 `ntt()` 多一步约减，两者输出**不相等**。比错了会一直假报失败 |
| `diff` 报「全部不同」 | 先怀疑**行尾**，别急着怀疑数值。所有数据文件统一用 LF（UNIX）行尾，写文件用 `"wb"` 不用 `"w"` |
| 仿真挂死不动 | 检查有没有无界 `while (done == 0)`，加计数护栏 |
| 板子不通 | 先跑官方 `19_uart_loopback` 例程，确认是工具链问题还是你的设计问题 |
| 板子插上了、串口也在，但烧不进去／没反应 | 上板要**同时**满足三件事，缺一样就烧不进去或看不出效果：① **外接 JTAG 下载器**接在 14-Pin 排针上（板上**没有** USB-JTAG，`USB_UART`／`USB_SLAVE` 两个口都**不能**下载程序）；② **启动模式拨码开关拨到 JTAG 档**；③ **底板 P5 跳 PL 档**（3–5、4–6 短接）。另外 **COM 口存在 ≠ PL 通路通** |
| 要重新综合才能上板吗 | 不用。官方 `19_uart_loopback` 自带一份**已编译好的 `.bit`**，器件正是板子的 `xc7z020clg400-2`，直接烧就能做「板子到底通不通」的冒烟测试 |
| 时序不收敛 | 降折叠度／加流水级／降目标频率。先出一个能跑的低频版本 |
| 上位机对仿真跑不通 | 别急着上板。仿真里都跑不通，上板只会更难查 |
| Vivado 报 `couldn't read file …`，或 ABC 报打不开临时文件 | **先怀疑仓库路径里的撇号**。本机路径是 `C:\Users\l'x\…`，那个撇号会被当成引号开头，把 Vivado 综合引擎的路径拼坏（`l'x` 变成 `lx`）。对策：**从仓库外的目录启动 Vivado**（`rtl/vivado/` 的脚本已经这么做了）。⚠️ **用 GUI 建工程也要建到仓库外**，否则上板那一步会中招 |
| 同一份代码，综合有时过有时不过 | Vivado 2020.2 的综合子进程会**间歇性**报「文件读不到」，而那个文件其实好好地在。**重跑一次就过** —— `rtl/vivado/run_folding_sweep.sh` 已内置 3 次重试，也会把上轮的报错打出来 |

### 降级顺序

**先砍功能深度，后砍文档。**

| 风险 | 降级方案 | 主责 |
|---|---|---|
| Vivado 装不上 / 板子不通 | 纯仿真演示 + 波形动画，报告里说明环境问题。**验证报告照样是完整的** | A |
| INTT 调不出来 | 只交 NTT 单核，把验证做扎实（正确性 20 分照样能拿） | A |
| 上位机写不完 | 用仿真波形截图代替串口实测 | B |
| 不做「折叠度可配置」 | 只交固定版本，少一个创新点 | A |
| 时间不够 | **优先保报告 + 视频 + 开源仓库**，这三样是过程分的载体 | C |

可以不做「折叠度可配置」，**但不能交不出报告**——功能砍了只丢单项分，文档烂了丢 30 分。

## 七、三人都要守的规矩

1. **每完成一小步就截图／录屏存下来** —— 既是 debug 抓手，也是报告和视频的素材
2. **每天花 10 分钟记 AI 协作日志** —— 这是 15 分，零成本，但过期补不回来
3. **不做完不合并** —— 保持仓库随时能跑，别让队友拿到跑不起来的东西
4. **答辩要能复述原理** —— AI 帮你写的代码，得让 AI 给你讲懂了再上板
5. **别中途换工具版本 / 换板子** —— 工程复现不了是致命伤
