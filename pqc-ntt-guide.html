01为什么是这个题

做一个 256 点的 ML-KEM 数论变换（NTT）硬件核：多项式进来，变换结果出去， 用官方测试向量逐点验证它对不对。 它小到能在七周内做完，又完整到能被官方标准独立判定对错 —— 这是本选题唯一、也是最大的价值。

赛道判断：你们之前搞错了

旧档案里写的赛道结构（基础能力 / 综合能力赛道）是 2025 年的。 2026 年指南的 AMD 赛道是三个，且「算法硬件加速」不再是独立赛道。

为什么是 PQC-NTT，而不是原先推荐的 ESN

可行性分析推荐 ESN，理由是「11/7 能交货」—— 那个判断在当时缺了评分权重这一维。补上后，决定性的一击来自可行性分析自己：

关键推理

串口带宽比计算核慢 3–4 个数量级，所以 「快多少倍」的叙事在你们这套载体上天生站不住。 既然倍率讲不响，就必须换一个不靠倍率的故事 —— 而 NTT 恰好有：常量时间实现天然抗侧信道。 硬件的数据无关时序是软件 KEM 实现做不到的，这个卖点比「快 N 倍」硬得多， 且直接落在 30 分的创新性上。

被否决的方向，以及为什么

视觉防抖 EIS。开源界端到端代码确实不存在（实测 0~2 个不相关结果）， 创新性很强 —— 但它输在另外三处：① 没有权威正确性判据（「画面看着稳」不是判据）； ② 板级工作量（摄像头 I2C、DVP 或 MIPI 时序、DDR/VDMA、HDMI 时序）正是 AI 帮不了的部分； ③ 厂商例程缺失。它输在「功能正确性」和「AI 杠杆」，不是输在「它是视觉」。

03数学与常数

参数总表

符号值含义

n256多项式次数
ζ17本原 256 次单位根

三个必须先读懂的陷阱

陷阱 1有符号中心化表示（int16，不是 uint16）

系数全部存成 [−q/2, q/2] 的有符号数，不是 [0, q−1]。 所以 zetas[0] 是 −1044 而不是 2285 —— 两者模 q 同余。用 uint16 存这张表，全盘皆错。

陷阱 2Montgomery 域缩放 —— 我在调研时踩了这个坑

NTT 中间结果不等于标准域的值。每级蝶形的模乘都带一个 R⁻¹ 因子， 所以硬件输出的 NTT 结果带一个常数缩放（标准 NTT × 某个 2 的幂）。

绝对不要拿硬件 NTT 的输出和 Python 里「干净的 NTT 实现」逐点比 —— 永远对不上。这是「怎么调都差一个常数」的经典死循环。

陷阱 3INTT 的缩放因子在哪个域

1441 是 128⁻¹ · R² mod q， 它必须配 fqmul（Montgomery 模乘）使用，不是普通模乘， 而且只在逆变换的输出端施加一次。

实测：fqmul(x, 1441) 的效果 ≠ x · 128⁻¹ mod q， 而是 x · R · 128⁻¹（普通域 512）。 用错域 → 结果整体差一个 R，KAT 必挂，但仿真「看着很对」。

正确的对拍方法

不要比中间值，要比一个数学上唯一确定的东西。推荐顺序：

  1. 黄金模型先行 —— Python 写一份和 RTL 用同一套算术的模型 （同样的有符号表示、同样的 Montgomery 约减、同样的域）， 不要写「教科书版 NTT」。
  2. 三层对拍，越靠前越容易 debug：
    • ① 模乘单元 —— 随机 (a,b)，硬件 == 黄金模型，精确相等
    • ② 多项式乘法 —— INTT(NTT(a) ⊙ NTT(b)) 对比普通学校式负循环卷积的 mod q 结果。 数学上唯一确定，不依赖任何实现约定 —— 这是最好的中间判据
    • ③ 官方 KAT —— 最终验收，.rsp 逐字节比对
  3. basemul 的 checkpoint（若做到那步）：参考实现里该值依赖内部表示， 不要直接比数值，比「乘法结果 mod q 相等」。

twiddle 表

完整 128 项 zetas 与 zetas_inv 见附件 rtl/zetas_tables.v。

  • zetas：已与 ref/ntt.c 源码前 32 项字节精确一致
  • zetas_inv：由 zetas 取模逆推导，满足 z · z⁻¹ ≡ 1 (mod q)
  • 但 zetas_inv 的层序未能复现 —— 必须打开 ref/ntt.c 的 invntt_tomont() 确认每层取哪一段 twiddle、 按什么顺序递减

参考实现的约减函数（逐字）

int16_t montgomery_reduce(int32_t a) {
  int16_t t;
  t = (int16_t)a*QINV;
  t = (a - (int32_t)t*KYBER_Q) >> 16;
  return t;
}

int16_t barrett_reduce(int16_t a) {
  int16_t t;
  const int16_t v = ((1<<26) + KYBER_Q/2)/KYBER_Q;
  t  = ((int32_t)v*a + (1<<25)) >> 26;
  t *= KYBER_Q;
  return a - t;
}

04系统架构

PC ──UART(115200)──▶ PS (裸机 C) ──AXI-Lite──▶ PL · 收/发测试向量 ┌──────────────────────┐ · 寄存器读写 │ NTT / INTT 核 │ · 逐点对拍 │ 参数化折叠 k │ │ 蝶形 × k 并行 │ ┌─────────────────────┤ 模乘/模约减单元 │ │ 片上 LFSR 激励源 └──────────────────────┘ │ (伪随机多项式) │ │ 结果校验 / 比对 ────────────┘ └─▶ 周期计数器 → 读回

两条通路

通路用途为何这样设计
正确性通路 PS 慢慢喂 KAT 向量、读结果回 PC 逐点对拍 115200 波特下 512 字节 ≈ 44 ms，慢但完全不影响正确性验证
吞吐通路 片上 LFSR 自生成激励 → 核全速跑 → 回读周期计数器 绕开串口带宽瓶颈，测出的是内核吞吐，可与文献对比

两个数分开报：内核吞吐（不受链路限）+ 端到端吞吐（注明链路速率）。 诚实且专业。

本选题最大的优势

板级工作量只有三件事：UART 回环、P5 跳帽、一个 AXI-Lite 寄存器组。 没有 DDR、没有 VDMA、没有摄像头、没有 HDMI。
