# B verification strengthening

本工具在 PC 上执行 RTL 仿真，不需要 FPGA 板卡或 Vivado。运行顺序为：新编译 C 参考程序 → 原始 RTL 基线 → 17 个 RTL 变异体 → 三档随机输入周期与正确性检查。任一步失败，整体验收失败。

在仓库根目录的 PowerShell 中执行，输出目录必须尚不存在：

```powershell
$env:PYTHONIOENCODING='utf-8'
python refsim/accept_strengthening.py --output ../B_strengthening_manual_01
```

需要 Python、gcc、iverilog、vvp；后二者支持自动查找 `C:/iverilog/bin`。预计运行数分钟，以本机实际耗时为准。再次运行请换新目录名，例如 `../B_strengthening_manual_02`，脚本不会覆盖已有证据。

正常结束应显示 `PASS: baseline; 17/17 RTL mutants detected`，随后注明 100 个随机输入加 3 个边界输入、三档均通过。最终 `acceptance.json` 的 `status` 应为 `pass`。请把最后的结果截图交给协作助手完成用户验收记录；不需要逐个阅读仿真日志。

## 变异测试判据与范围

用 `rtl/ntt_core` 的临时完整副本逐个加入一处明确故障，原件不改。目录内保留实际变异源码、替换前后文本、原始/变异文件 SHA-256、编译和运行命令、退出码及标准输出/错误。替换锚点必须且只能出现一次，源码变化后不匹配就停止，不会盲目修改。

采用现有 `polmul_param_tb.v` 的 **pe4 / FULL / 16 组 / 4096 系数**作为探测回归，FULL 路径包含 FNTT A/B、PWM2、INTT。每组 A/B 不同且具有较高系数多样性。期望由本次重新编译的原版 C 程序生成，并和冻结向量核对；最终逐项按 tau 排列比较，也检查多重集。必须先确认完全相同流程下的原始 RTL 通过，才开始变异。

17 种故障清单以 `accept_strengthening.py` 中的 `MUTATIONS` 为准，涵盖模加、模减、整数乘法、逆变换除二、蝶形选择与流水线、读写地址、twiddle 索引、bank 选择及串行接口排列。变异数量与机制用于检验回归对这些预先选定故障的识别能力；不代表全部可能错误的覆盖率。

分类严格区分：

- `detected_mismatch`：仿真正常完成且有 4096 个合法输出，但与 C 不同，保存首个差异和匹配计数。
- `detected_unknown`：仿真正常完成、输出条数完整，但输出包含 X/Z，说明故障使数据无效。
- `pass`：变异未被捕获，需要调查；对基线则是预期结果。
- `compile_error`、`simulation_error`、`invalid_output` 或工具超时：不计入成功捕获，整体验收失败。

此轮变异检测固定在 pe4/FULL；原有三档 × FULL/HALF 的 24576 系数回归仍由 `check_polmul_param.py` 提供，此处不重复宣称已对每个变异运行六组合。

## 周期和地址观察

固定种子 `20261018`，生成 **100 个不同的随机多项式**（系数 0..3328），再追加全零、全 3328、0/3328 交替三个边界输入。相同的 103 个输入分别送入 pe1、pe4、pe16，共 309 次 FNTT。连续装载、运算和读取，样本之间不复位。输入文件、生成种子、SHA-256 和每个样本的 C 答案均保留。

每次同时检查：

1. 从外层 `start_fntt` 脉冲到外层 `done` 的实测延迟为 907/235/72 拍。按仓库既有探针约定扣除接口流水线 3 拍，对应核周期 **904/232/69**。
2. 全部 256 个输出与本次编译的 C `poly_ntt` 一致。pe1 用已有 sigma 次序（组内 0,2,1,3），pe4/pe16 自然序；不通过猜首个非零值来对齐。
3. 运算窗口内逐拍观察 `raddr0/raddr1/waddr0/waddr1/raddr_tw/wen0/wen1`。每个样本必须具有完整窗口，同档所有样本的**有效写地址**、读地址、twiddle 地址及写使能序列必须完全一致；写使能为 0 的拍没有写访问，该写地址不参与有效地址比较。原始序列与有效序列的 SHA-256 均保存，原始输出保留逐拍记录。

开发时首次运行因“所有原始地址线必须一致”的断言失败。最终实测三档均为：第一次运算的开头 8 拍，与后续样本存在闲置写地址残留差异，对应写使能均为 0；后续 102 个样本的原始序列彼此一致。这是复位后的首次运算与连续运行的状态差异，不能据此称系数导致有效访存不同。最终检查保留原始序列差异数量，同时单独比较有效写访问；不删除这些拍、不对读地址或 twiddle 地址做屏蔽。此边界必须随结果一起说明，不能表述为“所有原始地址总线始终一致”。

静态核查依据：`KyberHPMNTT.v` 的 `OP_FNTT` 状态退出、`op_cntr` 和 `done` 只依赖状态与固定终值；`addressgenerator.v` 只接收时钟、复位及三个启动信号，其地址由状态/级/循环计数器产生；`KyberHPMNTT_top.v` 的慢跑使能依赖装载/读取请求与相位计数。运算数据进入算术通路，不作为这些调度逻辑的分支条件。算术模约减中的数据选择仍存在，不应称“整个设计无数据相关选择”。

这提供的是已观察输入下的固定延迟和所列地址信号一致性证据，加上人工源码核查。它不是形式化信息流证明，不覆盖所有可能输入，也不能证明功耗、电磁、故障攻击等侧信道安全；不测主机/串口/整套 ML-KEM 的固定时间，不代表已上板复核。

## 证据读取

- `acceptance.json`：最终状态、被测源码 SHA-256、变异详情和周期摘要。
- `baseline/`、各故障名目录：临时 RTL、完整命令、日志与单项结果。
- `mutations.json`：基线与 17 项逐项状态。
- `timing.json`：各档每个输入的周期、输出检查数、地址摘要。
- `timing_in.txt`、`timing_inputs.json`：原始输入及对应 C 答案。
- `timing_pe*.stdout.txt`：逐拍地址、周期和输出数据，便于追查。

工具不会读写串口或烧录板卡。`research/` 与 `rtl/` 的源文件仅复制、读取并检查哈希；任何输出都在显式指定的新目录内。
