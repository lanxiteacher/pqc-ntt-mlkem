## 一、AI 协作日志怎么写

**文件名**：`ai-log/YYYY-MM-DD_<谁>.md`，一天一个，**每人一个文件**。

**每条记五样**：

```markdown
## 14:20 演示页第一层蝶形画不出来

**问了什么**（原话贴，不要转述）
> 我在做一个 NTT 第一层蝶形的动画……数字排出来是乱的

**AI 答了什么**（摘要即可，关键那句贴原话）

**哪里不对**
它把 256 个数的配对规则当成了相邻配对（0-1, 2-3），
实际是**按位反转**配对（0-128, 1-129）。

**怎么发现不对的**
拿 `refsim/run_ntt_layers.sh` 导出的层序表一比，第 3 对就对不上。

**改完对不对**
改按位反转后对上了第一层。第二层的 twiddle 常数还是错的，见下一条。
```

**要点**：

- **卡住的时刻比顺利的时刻更有价值。** "AI 一次就给对了"那条几乎没有信息量，
  但也要记 —— 它是"顺利"的基线。
- **贴原话。** 你的提问、AI 的关键回复、报错信息 —— 转述会丢掉线索，
  而且转述过的日志评委能看出来。
- **记"怎么发现不对的"** —— 这是「自我纠错轨迹」，是评分点里点名的那一项。
- **一天 10 分钟就够。** 超时说明你在写作文，不是在记录。

## 提交格式（2026-10-17 定）

《选题指南》**没有规定**报告交 PDF / Word / Markdown（A 2026-10-15 全文逐词搜过，
`PDF` / `Word` / `Markdown` / `docx` / `文件格式` / `排版` / `页数` / `字数` 各 0 处命中；
见 `../logs/guideline_excerpts_2026-10-15.md` §〇）。所以由我们自己定：

| 项 | 决定 |
|---|---|
| **源文件** | 仓库里的 Markdown（`design/*.md`）—— 可 diff、可追溯、与代码同库 |
| **提交件** | **PDF** —— 版式固定、离线可开、图表不会因阅卷机器缺字体/插件而变样 |
| **不做** | 不交 Word（版式随 Office 版本漂移）；不只交 Markdown（评审环境是否渲染表格与图片不可控） |
| **生成时点** | W5「冻结与组装」：Markdown 冻结后再出 PDF，**不反过来改 PDF** |
| **生成方式** | ✅ **2026-10-18 实测通过**：`python report/build_report.py`（Markdown → HTML → 无头 Edge 打印 PDF）。依赖：Python 3、`markdown==3.11.1`、`pymdown-extensions==12.3`、Microsoft Edge（Windows 11 自带）。产物在 `report/build/`（已在 `.gitignore`，不进仓库）；`--html-only` 可只出 HTML。<br>实测（2026-10-21 重建，含 A 的 Phase 1 改动与 §4.11）：**59 页 / 4.0 MB**，10 张图（4 SVG 矢量 + 6 PNG）全部解析，八份源文件八个部分齐全，表格全部渲染。⚠️ 页数随内容与渲染环境变 —— 同一脚本 10-20 记的是 76 页、10-21 重建为 59 页（内容未减，末章参考文献在第 55 页）；**提交前以打开 PDF 的实际页数为准，文档里不写死** |
| **页码** | 草稿版**暂未加**（构建脚本先保证内容与版式）；W5 组装时用 Edge CDP 页脚模板或 PDF 叠加补「第 N 页 / 共 M 页」，**不手改 PDF** |

理由一句话：**评审看的是「能不能稳定打开、图表是否完整」**，
PDF 在这两点上最稳；Markdown 留在仓库里承担「可复现、可核对」。
两个格式各司其职，不是二选一。
