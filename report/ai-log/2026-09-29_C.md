## ⚠️ AI 上一轮写下的算式是错的：「t = zeta × b」

**哪里不对**

上一轮页面和我写的 `demo/README.md` 里，蝶形算式写的是 `t = zeta × b`。
**这是错的。** `fqmul` 是 Montgomery 乘，自带 **R⁻¹ = 169** 的因子；表里的 `zeta`
又在 Montgomery 域（`zetas[0] = 2285 = R`）。两个因子抵消之后，真实的 twiddle 乘法
才成立 —— 所以 `t` **不等于**普通的 `zeta × b`。

按旧写法算，README 里那个例子（`zeta = 1493, b = 2446`）得 3294；
而页面**同时显示**的 a′/b′ 对应的 t 是 **743**。页面自己跟自己对不上。

**怎么发现不对的**

AI 没有照抄旧页面的算式往下写，而是**先写了个探针脚本核 `fqmul` 到底等于什么**：

```
fqmul(zeta, b) = 1422        普通乘 (zeta × b) mod q = 166      ← 不相等
逆末级 fqmul(r, 1441) / r 的比值集合 = {512}                    ← 只有一个值
```

比值集合大小为 1 → 说明它是个**纯常数因子**而不是算错，那个因子就是 R⁻¹。
（顺带得到 512 = R/128，正好解释 `refsim/README.md` §七 里 RTL 的 INTT 与参考实现
差 R⁻¹ 那件事。）

**改完对不对**

- 算式改成 `t = fqmul(zeta, b)`，页面上加了说明框
- 用了同一个探针把**页面显示的全部数值**按新算式复算一遍：
  正变换 **28672** 个值、逆变换 **32768** 个值，**都是 0 处不符**
- 顺手在页面上加了一行**「页面自检」**：每次打开都把显示的数按页面自己印出来的
  算式复算一遍，结果直接印在页面上。以后谁改错算式，页面会自己露出来，不用靠人看

**对拍页上一个取舍**

全仓库 `*rtl_out*` 搜下来**只有 `fntt_rtl_out.txt` 一个** RTL 逐值落盘文件。
所以对拍页上只有 FNTT 那行标「本页复算」，INTT / PWM2 / FULL / HALF / 往返自检
标成「**引用**」并把出处（`refsim/README.md` §三）写在表里 ——
**不给没有落盘数据的运算编造逐值数据。** 想让它们也变成「本页复算」，
需要 B 那边给对应 testbench 加 `+dump=1`，尚未提。

### ⚠️ 三个 bug 都是自查出来的（脚本自己跑一遍就露了）

**① 行级明细被 `$(...)` 吞掉了。**

`res=$(awk '...')` 把 awk 的 stdout 收走做解析，
结果「**哪一行**不合规、**什么原因**」也一起被吞了，只剩下一个数字。
于是脚本输出「18 行不合规」，但不告诉你哪 18 行 —— 等于没用。
改法：明细写 `/dev/stderr`，只让那一行机读汇总走 stdout。

**② `gawk` 在 Windows 上读文件时会自动把 CRLF 折成 LF。**

所以 `sub(/\r$/, "")` 在 Windows 上是**空操作**，
`awk` 根本看不见 CR —— 脚本把一个**货真价实的 CRLF 文件判成了合规**，
还打了 ✅。这个如果没测出来，会直接误导人「行尾没问题」。
改法：**按字节数 CR**（`tr -dc '\r' | wc -c`），Windows / Linux 都准。
（顺带说明：那句 `sub` 保留着，是给 Linux 用的 —— 那边 awk 不替你剥 CR。）

**③ `command -v python3` 说「有」，实际跑不通。**

就是今天早上工具链自查的那个坑，换个地方又咬了一次：
PATH 里的 `python3.exe` 是 WindowsApps 的**跳转存根**，
`command -v` 认得它，一跑退出码 49、无输出。
脚本据此报「✅ python3」，然后给出一个「没有失败但也没真跑」的假通过。
改法：工具预检**真跑一下版本命令**，看退出码与输出，不看 `command -v`。

**共同点**：这三个都不是「写错了逻辑」，而是**「验证手段本身不可靠」**。
如果我只把脚本写完就交，三个都会留在里面。

**改完对不对**

三个脚本都用**仓库里的真实文件**测过：干净文件 exit=0；
`vref_00.txt` 抓到 18 行未补零并列出 `1:「74」`、`22:「b」` 等；
KAT 原件正确报出 4096 行 CRLF；`intt_batch_in` 的非退化统计
2374 个不同值 / 0.58%→0.15%，与 `refsim/README` §三 的表一致；
全常量文件被判 ❌；`check_reproducible.sh` 能 clone、能查产物、
能正确识别两个工具缺失。

**⚠️ 一处没验的要说清楚**：`batch_testbench.v` 是骨架，本机没有 iverilog，
**没有编译验证过** —— 已在那个文件与 `templates/README.md` 里写明，
套用时先跑最小例。
