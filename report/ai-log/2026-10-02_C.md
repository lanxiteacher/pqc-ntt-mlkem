## 浅色主题：只覆盖变量，布局一个字不改

**AI 答了什么**

`demo/ntt-view.js` 里三个页面的颜色**本来就集中在一组 CSS 变量**（`:root { --bg; --fg; ... }`），
只是有几处颜色是**硬编码**的（`.cell.chg` 的 `#f0c674`、`.cell.sel` 的 `#fff`、
`code` 的 `#f0c674`、`button` 的 `#232a34`）。

做法：

1. 把这些硬编码也提成变量（`--chg-fg` / `--sel-fg` / `--code` / `--btn-bg` …）；
2. 新增 `:root[data-theme="light"]`，**只覆盖变量**，不碰任何布局；
3. 三个页面都调 `NttView.css()`，所以在 `css()` 里统一认 URL 的 `?theme=light`。

**第一处取舍：为什么是「两套变量」而不是「两套 CSS」** ——
深色已经是能用的版本，重写一套浅色 CSS 等于把布局抄一遍，以后改布局要改两处、迟早漂移。
**共用布局、只换颜色**，深浅两版就不可能各走各的。

**验证**：深色版重渲染后与**已提交的原图**逐像素一致（见下面第二个坑）——
这也顺带证明了浅色改动**没有碰坏深色**。

## 截图脚本：两个去处、可裁切、红格数**数出来**

**AI 答了什么**

`demo/gen_shots.mjs` 原来只输出 4 张深色图到 `assets/`。改成：

- 每条截图带 `theme`（dark/light）与 `out`（assets/figures）——
  **同一张图两个去处，两边的命名规矩不同**（`assets/` 是 `日期_谁_一句话`，
  `report/figures/` 是英文小写下划线）；
- 带 `clip`（CSS 选择器）：报告版只截「标题 + 网格」一块。
  **为什么必须裁**：对拍页整页是 **2880×3614**（又瘦又长），进报告没法排；
- 带 `expectBad`：截图前断言 `#grid` 里的红格数 —— 对拍那两张要求 0 / 1。

**为什么要 `expectBad`**：图的名字本身在断言一件事（「全中」「抓出 1 个」）。
**如果只是截下来、不去核，就等于替图说了它没证明的话。** 昨天记过一条
「缩小到 1/4 看，两个红格也可能看成一个」—— **能用数出来的，就不要用看的**。
现在这条从「事后用 node 手核一次」升级成「脚本每次出图前自动断言」。

## ⚠️ 自查一：模板字面量里写了反引号，整个对拍页白屏

**哪里不对**

改 `compare.html` 时，我给新增的 CSS 加了一行**中文注释**，里面为了排版把一段选择器
用反引号括了起来：

```js
    /* ⚠️ 必须写成 .stage b.okfg —— ntt-view.js 里有 `.stage b { color:var(--fg) }`， ... */
```

**这段注释在 `extra.textContent = \`...\`` 这个模板字面量里面** ——
反引号**提前把模板字符串结束了**，整个 `<script>` 变成语法错误。

**怎么发现不对的**

改完我重跑 `node demo/gen_shots.mjs`，输出里出现：

```
✓ assets/2026-10-01_C_演示页对拍阴性对照抓出1个系数不符.png  (21 KB)   ← 只有 21 KB！
截图失败：clip 选择器没命中：main > div:first-child
```

**21 KB 是白的**（正常 720 KB）。我用之前写的一个 CDP 探针脚本去读计算样式，
它返回 `undefined` —— 探针里 `getComputedStyle(document.querySelector('.stage'))`，
`.stage` 是 `null` 才抛异常，说明**页面根本没建起来**。

**改完对不对**

把注释里的反引号去掉（改成普通文字），探针立刻返回正常 JSON，
`--ok-fg` 也解析成 `#9ed49e`，截图恢复到 720 KB。

**为什么值得记**：**注释写在模板字面量里，注释里的反引号就是代码**。
这类错编译不过、但没有编译器提示（HTML 内联 JS 没人 lint），
**只能靠「跑一遍看产物大小对不对」发现** —— 21 KB vs 720 KB 是它唯一的信号。

## ⚠️ 自查二（更值得记）：绿字被一个更具体的选择器盖掉，靠**逐像素比对**揪出来

**哪里不对**

原代码里，「256/256 全中」那几个字是绿色的，写法是**内联 style**：

```js
'<b style="color:#9ed49e">' + N + ' / ' + N + ' 全中</b>'
```

我做主题变量化时，顺手把它改成**类名**（颜色走 `var(--ok-fg)`）：

```js
'<b class="okfg">' + N + ' / ' + N + ' 全中</b>'
```

**颜色值一模一样，我以为等价。实际上不等价。**

**怎么发现不对的**（这条是全天的关键）

我重跑脚本后，`git status` 显示**两张对拍页的深色原图被改写了** ——
但另外两张（正变换/逆变换）**逐字节没变**。
**同样一段 CSS 重构，为什么只有对比页变了？** 这个不一致本身就是警报。

于是我把**已提交的那一版**从 git 里取出来，跟新渲染的**逐像素比**（自己写了个最小 PNG 解码器）：

```
dims 2880x3614 2880x3614
不同字节 4633 / 31224960，最大通道差 82
bbox  x 94..206  y 189..202 （逻辑 px）
```

差异**只有一行文字那么大**（x 94..206、y 189..202），正好是状态行 **`256 / 256 全中`**。
再采样那一点的**最绿像素**：

```
OLD 最绿像素 #65bc81    ← 是绿的
NEW 最绿像素 #d8ded5    ← 是前景灰，绿没了
```

**根因**：`ntt-view.js` 里有一条 `.stage b { color:var(--fg) }` ——
选择器**权重 (0,1,1)**，比我新写的单类 `.okfg` **(0,1,0)** 高，**把绿色盖掉了**。
原来用内联 style（比任何选择器都硬）时它赢；**换成类名就输了**。

**改完对不对**

加两条更具体的选择器 `.stage b.okfg` / `.stage b.errfg`（权重 (0,1,2)），并**在注释里写明原因**
（免得后人再「顺手简化」回去）。改完重跑：

```
git diff --stat -- assets/     →  空
```

**4 张深色原图现在与已提交版本逐字节一致。**

**为什么这一条最值得记**：

1. **「颜色一样」不等于「渲染一样」。** 内联 style 和类名的**优先级不同**，
   改写法就可能被别的选择器盖掉 —— 这类 bug **不报错、不崩、只是悄悄变灰**。
2. **发现它靠的不是看，是「比」。** 我是因为「同样重构，为什么只有两张图变了」
   这个**不一致**起疑，才去逐像素比的。**「新旧本该一致却不一致」是个免费的检查点** ——
   截图重生成后跟仓库里的老图 diff 一下，这次正好把 bug 逼了出来。
3. **回归基线就在仓库里。** 已提交的截图就是「正确渲染」的基线，
   不需要额外准备。**每次重生成图片，都先 diff 一遍旧版**，
   这条以后可以当常规动作。
