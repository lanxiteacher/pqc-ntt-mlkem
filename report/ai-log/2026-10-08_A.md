**★ 「写死边界」这一步是这条的重点。** 原来的状态是「**两句话各自都对、但没人把它们摆在一起**」：
协议侧没跑过 / 真板子侧跑过了。**这看上去像互相矛盾，其实是两码事。**

## 八、工具坑两枚（今天都咬到了）

**① 我把 `status/status.json` 写坏了，而它是静默的。**

在 JSON 字符串值里写了裸的 `"`（`--check "#PMUL NTT 1"`）—— 必须转义。
**第一次我还试图用反斜杠加反引号去转义** —— 那在 JSON 里是**无效转义**，也是错的。

**真正值得记的不是转义怎么写，是它的后果**：

```
python -c "...json.load..." && node status/gen_status.mjs >/dev/null && node ... --check
```

`&&` 链在**第一个**命令就断了 ⇒ **`index.html` 没有重出、整批没有提交**。
**一个字符的语法错，让后面每一步都静默地没发生** —— 而屏幕上只有一行 traceback。

⇒ 对策：**改完结构化文件，立刻单独验一次**（`json.load`），不要等到提交前那一步才顺带验。

**② `python` 眼里的 `/tmp` 和 Git Bash 眼里的 `/tmp` 不是同一个目录。**

我用 Python 的 `open('/tmp/msg.txt','wb')` 写提交信息，再用
`git commit -F /tmp/msg.txt` —— git 报 **`could not read log file`**。
原因：Python 把 `/tmp` 当成**当前盘根下的 `\tmp`**（落到 `C:\tmp`），
而 Git Bash 把它解析到 `C:/Users/l'x/AppData/Local/Temp`。

**⇒ 跨工具传文件一律写绝对路径**（`C:/tmp/...`），别用 `/tmp` 这种两边各有各的解释的写法。
