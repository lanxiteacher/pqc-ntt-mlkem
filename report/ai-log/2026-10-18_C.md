## 二、做法：一个脚本、两条命令

新增 `report/build_report.py`：

1. 按固定顺序读 `report/design/00`–`07` 八份 Markdown；
2. 用 Python-Markdown 转 HTML（`tables` / `fenced_code` / `pymdownx.tilde` 等扩展）；
3. 套一份 A4 打印 CSS（中文字体、表头灰底、表格不跨页断行、代码块折行、每章另起一页）；
4. 调无头 Edge 的 `--print-to-pdf` 出 PDF。

```bash
python report/build_report.py              # HTML + PDF → report/build/
python report/build_report.py --html-only  # 只出 HTML
```

产物在 `report/build/`，已加进 `.gitignore` —— **产物不进仓库**，源文件与脚本进仓库。
这与项目一贯的口径一致：可复现的是「怎么生成」，不是「生成出来的那个大文件」。

**一个关键技术点：相对路径。**
`design/*.md` 里的图片写的是 `../figures/architecture.svg`，链接写的是 `../../rtl/...`。
构建产物如果在 `report/build/`，与 `report/design/` **同深度**，这些路径原样就能解析。
另外在 HTML `<head>` 里加了 `<base href="file:///.../report/design/">`，
让浏览器始终按源文件所在目录解析 —— **不需要改写任何一条路径**。
这比「构建时批量替换路径」少一个出错面。

## 五、自我纠错（4 处）

### 1 控制台输出用了 emoji，Windows GBK 直接报错

脚本第一版打印 `✅ HTML：...`，在本机 Git Bash 下抛
`UnicodeEncodeError: 'gbk' codec can't encode character '✅'`。
改成 ASCII 的 `OK  HTML:` / `ERROR: ...`；同时在脚本开头把 `stdout` 重设为 UTF-8，
让中文提示在 Git Bash 里也不再变乱码。
**教训**：这是 Windows + GBK 控制台的老问题；脚本的**机器可读输出**不要用 emoji，
中文正文不受影响。

### 2 「先定路径再写转换」差点变成批量替换

第一版想在构建时把所有 `../figures/` 重写成 `figures/`。写到一半发现：
**只要产物与 `design/` 同深度，路径根本不用改**；再加一个 `<base>` 就完全不用碰源文本。
改掉之后，脚本里没有任何路径替换逻辑 —— 少一个会随目录调整而失效的环节。

### 3 为了「检查 PDF」装 PyMuPDF，装到一半卡住

验证 PDF 时先 `pip install pymupdf`，后台安装长时间不返回。
没有继续等：停掉，改用纯 Python 的 `pypdf` 读页数与文本。
**教训**：**验证工具**不该阻塞主交付；能用一个轻量替代就先跑起来。
`pypdf` 只用于本次检查，**没有写进构建脚本的依赖**。

### 4 页码没有「顺手做完」，也没有假装做完

Edge 的简单 `--print-to-pdf` 不带页码；Chromium 不支持 CSS 的
`@bottom-center { content: counter(page) }`。要加页码得走 CDP 页脚模板或 PDF 叠加，
那是另一段代码与一次新的验证。
今天**明确写成 W5 项**（`report/README.md` 的「页码」行），
而不是在日志里写「排版完成」。**草稿能看 ≠ 提交件完成。**
