## 二、B 的 J01 / J02 / J03：性能主张先改口径，再改数

三处根子都在 `metrics/gen_pareto.mjs`。先改生成器，再让报告与图跟着重生成。

### 2.1 J01：撤回「FPGA 比 CPU 低两个数量级」

原 §3.10.5 用 CPU 的 45 W TDP 假设 × 4.05 µs ≈ 182 µJ，去比 FPGA 的 vectorless
动态能量 0.31–0.36 µJ，得出「低两个数量级」。B 指出两边边界不一致
（TDP 假设 vs 工具估算、纯计算窗口 vs 整趟事务、活动率未标定）。

改法：保留六版位流功耗表作为**趋势分析**，CPU 数字降为**敏感性假设**，
并新增一张两行对照表说明「纯计算窗口」和「一次真实事务」两种比法方向相反；
明确写「本轮不主张 FPGA 比 CPU 省电」。CPU 侧数值随 J04 一起更新为 217 µJ。

### 2.2 J02：吞吐分三层，f/CC 不再叫整机吞吐

新增 §3.10.3「能算多快 ≠ 能交付多快」：

| 层 | 定义 | pe1 @80 MHz | pe4 @75 MHz | pe16 @62.5 MHz |
|---|---|---|---:|---:|
| ① 纯计算 | 周期数 ÷ 频率 | 11.30 µs / 88,496 NTT/s | 3.09 µs / 323,276 | 1.10 µs / 905,797 |
| ② 装载→读出（下界） | (256 + 周期 + 256) ÷ 频率 | 17.70 µs / 56,497 | 9.92 µs / 100,806 | 9.30 µs / 107,573 |
| ③ 真实串口事务 | 实测墙钟（pe1） | 0.250 s @115200 / 0.079 s @921600 | 未单独实测 | 同左 |

② 的假设写死：装载/读出各 1 系数/拍、不重叠、不计控制开销 —— **是下界**。
报告、CSV、图里的「吞吐」列全部带上层名；深档位被 256 拍装载 + 256 拍读出拉平
（pe16 的 ① 是 pe1 的 10.2×，到 ② 只剩 1.90×）。

### 2.3 J03：ATP 改成 LUT·cycle + LUT·µs，并说明只计 LUT

- `LUT·cycle = LUT × 周期`：面积 × **周期**，与频率无关；657,208 / 464,000 / 615,618，
  pe4 最低（0.706× pe1）。
- 新增 `LUT·µs = LUT × 周期 ÷ 板上频率`：面积 × **计算时间**；
  8,215 / 6,187 / 9,850，pe4 仍最低（0.753× pe1），但**这是另一个量**，不能把倍数搬来搬去。
- 表里补 FF / DSP / BRAM 三列，并注明 ATP **只计 LUT**；
  「pe4 最优」限定为「三个已测配置、只计 LUT 的指标」。

## 三、J04：CPU 基线改成与硬件同语义

原有 `metrics/bottleneck_ref_timing.c` 反复调**裸 `ntt()`**：不约减、每轮输入是上一轮输出。
B 指出这与硬件的 `#NTT`（= `poly_ntt()`）不是同一个任务，也不能反复拿越界输入计时。

改法：

- 计时目标改成 **`poly_ntt()` 语义**（`ntt()` + 256 次 `barrett_reduce`）；
- **每轮先把合法输入（系数在 [0,q)）memcpy 回工作数组**；
- **输入准备与计算分开计时**（512 B memcpy 约 0.01 µs，已从净计算中扣除）；
- 输出带 checksum 与越界计数，`bad != 0` 直接失败；
- 原始轮次写 `metrics/data/bottleneck_ref_raw.csv`（UTC、轮次、prep/total/net ns、
  checksum、CPU、Python、gcc）。

本机结果：**4.83 µs**（3 轮 × 200,000 次中位；AMD Ryzen 9 7945HX，gcc 16.2.0 `-O2`，
电源模式未控制）。报告里所有 CPU 倍数与能量假设随之更新：

| 项 | 旧（裸 ntt） | 新（poly_ntt） |
|---|---:|---:|
| CPU 单次 | 4.05 µs | **4.83 µs** |
| pe1 相对 CPU | 慢 4.5–5.4× | **慢 3.7×** |
| pe4 相对 CPU | 慢 1.1–1.4× | **同量级（0.96×）** |
| pe16@50 / @62.5 | 快 2.4–2.9× / 3.0–3.7× | **快 3.5× / 4.4×** |
| CPU 45 W 假设能量 | 182 µJ | **217 µJ** |

并明确写：这是**便携 C 参考实现**，不是 AVX2 优化软件，结论不暗示已击败优化实现。
