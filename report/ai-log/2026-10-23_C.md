## 10:10 停下来量分布，而不是挑一个好看的数字

**问了什么**
> 同一台机器、同一个二进制，为什么三次读数能差 20%？报告该引哪一个？

**怎么查的**
连跑 8 次 `bottleneck.py`，记下每次会话的中位：

```
4.02  4.04  4.67  4.85  4.67  4.82  4.67  4.98
```

同一次会话内部的 3 轮很稳（相差 <2%），**跨会话**才跳。CPU 是 Ryzen 9 7945HX（笔记本），
电源模式未控制 —— 这是调频/温热状态差异，不是代码问题。

**结论**
- 不能挑 4.01：那是机器偶然进入高频状态的两次读数，不能代表常态；
- 也不能继续用单次会话的 4.83 却让生成器每次写出别的值 —— 冻结日一重跑就又「不一致」。
- 正确做法：**报告引用跨会话累计中位**，原始轮次全部留档，并把噪声写进正文。

## 10:40 改 `metrics/bottleneck.py`：原始轮次从「覆盖」改成「追加」

**原来的行为**
每次运行 `write_ref_raw()` 用 `"w"` 覆盖 `data/bottleneck_ref_raw.csv`。
上一轮的原始证据直接消失 —— B 的 J04 要的「每轮时间可复算」其实只保住了最后一次。

**改法**
1. 追加写入（表头只在文件不存在时写），新增 `session` 列标识一次运行；
2. `aggregate_ref()` 读全部历史轮次，取**累计中位**；
3. 读数噪声 ±0.2 µs，所以中位/最小/最大统一取到 **0.1 µs**；
4. 新增 `--record`：**默认只读历史、不追加**，只有显式 `--record` 才记新会话。
   这样冻结日重跑不会让报告值再跳 —— 这是我自己踩出来的：第一版无条件追加，
   连跑 4 次把中位从 4.82 推到 4.83，报告又对不上了。

**中间改错两次（都是自己读输出发现的）**
- 第一版按 `utc[:16]`（分钟）分组会话，连续重跑被并成一批，打印「跨 2 次会话 12 轮」对不上；
  → 改成显式 `session` 列。
- CSV 那一行格式串换了占位符却忘了换参数，输出成「跨 3 次会话 / 200000 轮」；
  → 参数改为 `(sessions, rounds)`。

**结果**
`跨 5 次会话 / 15 轮，中位 4.80 µs（4.70–5.10）`，连续两次重跑都是 4.80。

## 13:30 报告 PDF：页码/页眉

**约束**
Chrome/Edge 无头打印不支持 CSS `@page` 的 margin box（`@bottom-center` / `counter(page)`），
所以不能在 HTML 里直接写页码。仓库里原来的说法是「W5 用 Edge CDP 或 PDF 叠加补」。

**做法**（写进 `report/build_report.py::add_page_furniture`）
1. 先照常把正文打成 PDF，用 pypdf 数页数 N；
2. 让同一条 Edge 再打印一份 N 页的叠层 HTML（每页只有页眉/页脚，A4、零边距）；
3. pypdf 逐页 `merge_page` 合并，页数不等就**拒绝合并**并报错（宁可失败，不要页码错位）。
页码格式「第 N 页 / 共 M 页」，页眉作品名，**封面不编号**。

**顺手查出一个排版 bug**
`h1:first-of-type { page-break-before: avoid; }` 本意是「第一个 h1 不另起页」，
但每章各自包在 `<section>` 里，`first-of-type` 在每个 section 内都命中 ——
**所有章都不另起页**。改成 `section.chapter:first-of-type h1` 后，每章正常另起页，
页数 61 → 64。

**书签**
按「页首即章标题」找各章起始页，写 8 个 outline。第一次只认出「附录」——
因为第 1 页顶部是构建说明，「封面与摘要」不在行首；加了一条兜底。

**验证**
`pypdf` 抽取全文：`4.80 µs` 10 处、`4.83 µs` 0 处、`208,333` 1 处；64 页、无空白页；
8 个书签页码 1/5/10/22/39/48/53/61；最后一页页脚「第 64 页 / 共 64 页」。
