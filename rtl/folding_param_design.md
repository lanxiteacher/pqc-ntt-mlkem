# 参数化折叠度 NTT 核 · 设计说明

> 状态：**设计定稿，待实现**（2026-09-29）
> 主责：A ｜ 目标器件：`xc7z020clg400-2`（正点原子领航者 ZYNQ，125 个 IOB）

## 一、目标与验收判据

把上游**三份手工复制**的设计（`rtl/pe1/` `rtl/pe4/` `rtl/pe16/`，合计 7638 行、三个独立目录树）
改造成**一份**以 `PE_NUMBER` 为参数的 RTL，三档都能综合进板上那颗 7020 并放得下。

**验收判据**（三条全过才算完成）：

| # | 判据 | 怎么验 |
|---|---|---|
| 1 | 三档综合通过，**Bonded IOB ≤ 125** | `rtl/vivado/run_folding_sweep.sh`，看 reports 里的 IOB 数 |
| 2 | 三档的**周期数与上游逐拍一致** | 探针实测 FNTT / PWM2 / INTT 的 `CC`，与下表逐个对齐 |
| 3 | 三档**功能对拍通过** | pe1 现有的 FIPS 203 KAT 验证链扩到 pe4 / pe16 |

判据 2 的基准值（上游实测，`rtl/vivado/折叠度对比表.md`；**右三是 2026-09-29 从顶层实测回来的**）：

| | FNTT_CC | PWM2_CC | INTT_CC | 实测 FNTT | 实测 PWM2 | 实测 INTT |
|---|---:|---:|---:|---:|---:|---:|
| pe1 | 904 | 647 | 904 | ✅ 904 | ✅ 647 | ✅ 904 |
| pe4 | 232 | 167 | 233 | ✅ 232 | ✅ 167 | ✅ 233 |
| pe16 | 69 | 47 | 71 | ✅ 69 | ✅ 47 | ✅ 71 |

> 实测由 `rtl/probes/run_probes.sh` 段 ⑨ 直接在 `KyberHPMNTT_top` 上量
> （顶层 `done` 拍 − `start_*` 起点 − 3 = 核 `CC`），每次跑自动比对这 12 格。
> INTT 那一格是新加的 `-DWITH_INTT` 腿；FNTT/PWM2 取自 `-DWITH_PWM2` 那趟。
> **判据 2 = 通过（12/12）。**

> **判据 2 是这次重构的主安全网。** 周期数对折叠度极其敏感（任何一处地址公式或 stall
> 写错都会改拍数），而它又几乎零成本可测。三档 CC 全对，说明折叠算法本身没被改坏。

## 二、问题陈述：为什么必须做

### 2.1 接口宽度随折叠度线性增长 → pe16 放不下

上游把 `din` / `dout` 做成 `[12*PE_NUMBER-1:0]`：

| 档 | din + dout | 控制信号 | 合计 IOB | 板子可用 | 占比 |
|---|---:|---:|---:|---:|---:|
| pe1 | 24 | 13 | 37 | 125 | 29.6% |
| pe4 | 96 | 13 | 109 | 125 | 87.2% |
| pe16 | 384 | 13 | **397** | 125 | **317.6%** |

pe16 的 `place_design` 在 IO 阶段直接失败。对照实验已坐实这是**封装引脚预算**问题而非逻辑问题：
同一份网表放到 Artix-7 `xc7a200tffg1156-3`（500 IOB）就布完了，而 pe16 的 LUT 只占 7020 的 15.9%。

### 2.2 ⚠️ `PE_NUMBER` 参数是**假的**

三个核文件都写了 `#(parameter PE_NUMBER=1/4/16)`（`rtl/pe1/KyberHPM1PE.v:30` 等），
但它**只用于数组维度和 generate 循环上界**，**从来没传进 `addressgenerator`**。
地址位宽在核里也是硬编码的（`rtl/pe4/KyberHPM4PE.v:91` 写 `reg [5:0] dw0 [...]`）。

**后果：今天把 `PE_NUMBER` 改成 8，地址生成器不会跟着变，设计直接错。**
所以「折叠度可配置」这句话在当前代码上是不成立的 —— 本设计要把它变成真的。

### 2.3 三份手工复制的漂移

`modred.v` 在 pe1 里**缺了**上游的 CC0 版权注释头（pe4/pe16 有）。
合并时统一，正好把许可证口径理顺。

## 三、关键分析结论

### 3.1 地址数学：三档是**同一个公式**

定义折叠参数：

```
L = log2(128 / PE_NUMBER)        pe1 → 7 ｜ pe4 → 5 ｜ pe16 → 3
```

`addressgenerator.v` 里的地址公式、恒等门限、twiddle 递增规则都是 **L 的表达式**；
三份文件里看似各不相同的常数代进去就统一（**唯一的例外是 twiddle 表的位宽**，见 §3.3）。

下表每一条都在三份源码里逐一核过。`S` = `c_stage`（**三档都是 0..6，在 6 处饱和**）。

#### （a）位宽与常数

| 写死的东西 | pe1（L=7） | pe4（L=5） | pe16（L=3） | 统一式 |
|---|---|---|---|---|
| `c_loop` 位宽 / 终值 | 7 / 127 | 5 / 31 | 3 / 7 | `L` / `2^L-1` |
| `raddr` / `waddr` 位宽 | 8 | 6 | 4 | `L+1` |
| 地址切片（低段） | `[6:0]` | `[4:0]` | `[2:0]` | `[L-1:0]` |
| 乒乓翻转位 | `[7]` | `[5]` | `[3]` | `[L]` |
| `c_tw` 初值（前向 / 逆向） | 127 / 254 | 95 / 190 | 39 / 78 | `T(L)` / `2·T(L)` |

#### （b）恒等门限 —— **读口与写口是四条不同的线**

| 位置 | pe1 | pe4 | pe16 | 统一式 |
|---|---|---|---|---|
| FNTT `raddr`（读） | `S==6` | `S>3` | `S>1` | `S >= L-1` |
| FNTT `waddre/waddro`（写） | `S==6` | `S>4` | `S>2` | **`S >= min(L,6)`** |
| INTT `raddr` 前置恒等 | **无此支** | `S < 2` | `S < 4` | `S < 7-L` |
| INTT `waddre/waddro` 前置恒等 | **无此支** | `S < 1` | `S < 3` | `S < 6-L` |
| INTT 读/写共用的末级恒等 | `S==6` | `S==6` | `S==6` | `S == 6`（**三档相同**） |

> `min(L,6)` 里的 `min` 是必需的：pe1 的 `S` 在 6 饱和，而 pe4 的 `L-1=4` 但 `S` 也一路走到 6，
> 两者必须落在同一条线上。代回去逐个核过：pe1 → `S>=6` ✓、pe4 → `S>=5` ✓、pe16 → `S>=3` ✓。
>
> ⚠️ **INTT 的读口与写口门限差一级**（`7-L` vs `6-L`）。写口在 `S = 6-L` 那一级
> **仍在置换**，而那一级恰好是公式的退化点（移位量为 0）。这是上游的真实行为，**不是笔误**。
>
> ⚠️ **FNTT 在 `S = L-1` 那一级，读口与写口故意不一致**：读口取恒等，
> 而 pe4/pe16 的写口**仍在置换**（退化成 `2*(c_loop>>1)`），只有 pe1 的写口也取恒等。
> 重构时必须逐档保持，**不要「顺手统一」**。

#### （c）置换的移位量

| | pe1 | pe4 | pe16 | 统一式 |
|---|---|---|---|---|
| FNTT `raddr`：掩码 & 项一 | `6-S` | `4-S` | `2-S` | `L-1-S` |
| FNTT `raddr`：项二 | `7-S` | `5-S` | `3-S` | `L-S` |
| FNTT `waddr`：右移 | `7-S` | `5-S` | `3-S` | `L-S` |
| FNTT `waddr`：左移 / 掩码 | `6-S` | `4-S` | `2-S` | `L-1-S` |
| INTT `raddr`：掩码 & 项一 | `S+1` | `S-1` | `S-3` | `S+L-6` |
| INTT `raddr`：项二 | `S+2` | `S` | `S-2` | `S+L-5` |
| INTT `waddr`：右移 | `S+2` | `S` | `S-2` | `S+L-5` |
| INTT `waddr`：左移 / 掩码 | `S+1` | `S-1` | `S-3` | `S+L-6` |

> 行号（以源码为准）：读口 `raddr` 块 —— `rtl/pe1/addressgenerator.v:227-247`、
> `rtl/pe4/addressgenerator.v:253-275`、`rtl/pe16/addressgenerator.v:292-314`；
> 写口 `waddre/waddro` —— `rtl/pe1/addressgenerator.v:313-343`、
> `rtl/pe4/addressgenerator.v:330-364`、`rtl/pe16/addressgenerator.v:373-407`。

**INTT 与 FNTT 的置换方向相反**：FNTT 的移位量随 `S` **递减**，INTT 随 `S` **递增**。
这与「正逆变换共用同一张 `zetas[]`、只是读的方向相反」是同一件事。

#### （d）三档逐字相同的部分（直接写一份即可）

- `raddr` / `waddr` 在 `start_*` 时清零
- `waddr` 的银行位翻转：`waddro[L-1:0] == 2^L-1 && c_loop == 0 && 状态 ∈ {FNTT, INTT}` 时取反
- `brsel` / `brselen` / `wen` —— FNTT 与 INTT 期恒为 `brsel = c_loop[0]`、`wen = 1`、`brselen = 1`；
  PWM2 期 `wen = (c_pwm == 3)`、`brsel = brselen = 0`
- `raddr_tw` = `c_tw` 打一拍（`shiftreg`，含 IDLE 期）

#### （e）`c_tw` 的递增规则也是 L 的表达式

前向（FNTT）：

```
S == 0   → 保持
L-S >= 1 → 仅当 c_loop[L-S-1:0] == 2^(L-S)-1 时 +1
L-S <= 0 → 每拍 +1
```

逆向（INTT）：

```
S == 6   → 保持
S <= 5   → c_loop[0]==0 ? +1 : (c_tw - 1 + ((c_loop[N-1:0]==2^N-1) << 1))，N = S+L-5
```

三档逐项核过。⚠️ 有两处**写法不同但语义等价**，重构时**不要当成 bug 去「修正」**：

- pe4 的 `S=0,1` 与 pe16 的 `S=0..3` 直接写成裸 `+1` —— 那是 `N <= 1` 时三元表达式两支同值的化简
- pe4/pe16 在 `S=5` 处省掉了 `<<1` 项 —— 那是 `N >= L` 的死分支；
  **pe1 在同样的位置仍然写着这一项**（同样是死分支）。按各自原样抄写。

**决定性数值证据**：twiddle 计数器的前向初值应当是

```
T(L) = Σ_{S=0}^{min(6,L-1)} (2^S − 1)  +  Σ_{S=L}^{6} (2^L − 1)  +  7
```

算得 `T(7)=127`、`T(5)=95`、`T(3)=39` —— 与三份文件里实际写的
`9'd127`（`rtl/pe1/addressgenerator.v:119`）、`8'd95`（`rtl/pe4/addressgenerator.v:129`）、
`7'd39`（`rtl/pe16/addressgenerator.v:152`）**分毫不差**。
三者同时命中同一个非平凡公式的概率可忽略，据此判定三份是同一算法的三个实例。

### 3.2 两处**不是** L 的函数（真结构分歧）

| | pe1 | pe4 / pe16 |
|---|---|---|
| **PWM2 地址** | 双读口 `raddr` + `raddr_b`，写地址受 `c_pwm` 调制；另吐 `raddr_b`、`c_loop_pwm` 两个顶层要用的信号 | **退化为恒等扫描** `raddr <= c_loop`，`waddre = waddro <= c_loop` |
| **FSM 结构** | 4 态、2 位编码，**无 stall 状态** | 有 stall 状态：pe4 加 `STL0/STL1`（6 态），pe16 加 `STL0/STL1/STL2`（7 态、3 位编码）并配 `c_stl` 计数器 |
| **BROM 表内容** | 382 条 × 12 位 | 222 条 × 48 位（pe4）／86 条 × 192 位（pe16）。**三张表互不相同，且不是彼此的打包或连续切片** |

- **PWM2 分歧**是数据布局决定的：PE=1 时「点乘 + 折叠最后一阶」的数据重排
  必须由地址生成器显式完成；PE≥4 时被并行度免费吸收。
- **stall 分歧**：三档都在「一轮扫完」的时刻（`c_loop == 2^L-1`）决定要不要多停一拍，
  但**停的条件三档各不相同**：

  | | FNTT 在哪儿停 / 停几拍 | INTT 在哪儿停 / 停几拍 |
  |---|---|---|
  | pe1 | **一处都不停** | **一处都不停** |
  | pe4 | `S == L-1`，1 拍 | `S == 0`，1 拍 |
  | pe16 | `S <= L-1`，**每级 2 拍** | `S <= L-1`，1 拍；`S ∈ {4,5}`，2 拍 |

  （pe1 那两处 `S == L-1` 的位置上**没有** stall —— 这正是它不能由 L 唯一决定的原因。）

- **BROM 分歧**（2026-09-29 实测补记，复现脚本 `rtl/ntt_core/tools/check_brom.py`）：
  三张 twiddle 表的**内容**也不同，且**不是彼此的打包或连续切片**。

  | | 条目数 × 每组字数 | 「一组内全同」的条目 | 能在 pe1 扁平表里找到连续匹配的 |
  |---|---|---|---|
  | pe1 | 382 × 1 | — | — |
  | pe4 | 222 × 4 | 126 条（首个非全同在第 63 条） | **只有 32 条：下标 190–221** |
  | pe16 | 86 × 16 | 30 条（首个非全同在第 15 条） | **只有 8 条：下标 78–85** |

  两档能匹配的都只是**尾段**，且**都从 pe1 扁平表的同一下标 254 起**
  （pe4 斜率 4、pe16 斜率 16）—— 254 正好就是 §3.3a 里那个「实际用到的最大 `c_tw`」。

  也就是说：**下标 ≥254 的尾段是斜率 = `PE_NUMBER` 的直通打包；
  254 之前的那一段是折叠造成的 twiddle 共享**（一组内若干个蝶形共用同一个 twiddle），
  共享的规律随折叠度变化，**推不出统一式**。

→ 这三处**只能分支保留**，不能强求统一式。

### 3.3 ⚠️ twiddle 表的位宽与内容**都不是** L 的函数

**（a）地址位宽。** `c_tw` / `raddr_tw` 的位宽三档是 **9 / 8 / 7**，而 `BROM.v` 的地址位宽正好也是 9 / 8 / 7
（`rtl/pe1/BROM.v:16`、`rtl/pe4/BROM.v:17`、`rtl/pe16/BROM.v:17`）。

实际用到的最大 `c_tw` 是 **254 / 190 / 78**，需要 8 / 8 / 7 位 ——
**pe4、pe16 刚好够用，pe1 多留了 1 位**。

所以这一组位宽是上游**手工选**的，推不出统一式（BROM 深度 512/256/128 同理，
源码注释里的 "222 is enough" / "86 is enough" 说明是人工挑的 2 的幂）。

**处置：单独开一个参数 `TW_ADDR_W`（9 / 8 / 7），不要假装能从 `L` 算出来。**

⚠️ 三者必须始终一致：`c_tw` 位宽 == `raddr_tw` 位宽 == `BROM` 地址位宽。
漏改一处 → 读数越界 → **读飞**（这就是风险表 R4）。

**（b）数据位宽。** `BROM` 的 `dout` 位宽 = **`12 * PE_NUMBER`**
（12 / 48 / 192）—— 一拍读出的是一整组蝶形要用的全部 twiddle。这个是能推出来的。

**（c）表内容。** 见 §3.2 最后一条：三张表**互不相同**，推不出统一式。
表是静态数据，**逐字保留上游原表**是唯一 bit-exact 的做法：
`BROM.v` 里用 `generate` 按 `PE_NUMBER` 分三支，各放一份原表（脚本从上游文件
逐字提取生成，不手抄）。

> 判定依据：`rtl/ntt_core/tools/check_brom.py` 把三张表抠出来做匹配 ——
> pe4 按 4 值一组、pe16 按 16 值一组，去 pe1 的扁平表里找连续切片。
> 若它们是 pe1 表的打包，**每一条都该命中**；实际 pe4 只命中 32/222、pe16 只命中 8/86。

## 四、架构

### 4.1 目录

新建 `rtl/ntt_core/`（一份，替掉三个目录）：

```
rtl/ntt_core/
├── KyberHPMNTT.v        核    #(parameter PE_NUMBER=1)
├── KyberHPMNTT_top.v    顶层  输入/输出寄存 + 固定 12 位接口 + 序列化器
├── addressgenerator.v   参数化  #(parameter L, TW_ADDR_W)
├── BRAM.v               #(parameter ADDR_W)            数据位宽恒 12，深度 2**ADDR_W
├── BROM.v               #(parameter PE_NUMBER, TW_ADDR_W)  三张原表走 generate（§3.3c）
├── butterfly.v  modadd.v  modsub.v  modred.v  modmul.v  intmul.v
└── dt0.v dt1.v dt2.v dt3.v  FA.v HA.v div2.v shiftreg.v
```

**新树里与上游重名的模块一律加 `ntt_` 前缀**（`ntt_BRAM` / `ntt_BROM` / `ntt_addressgenerator` …）——
Verilog 没有命名空间，新旧同名的话「新旧并排逐拍对拍」根本编译不过。

- 叶子模块三档**全部只差空白或注释**（2026-09-29 逐文件 `cmp` 实核）：
  `butterfly` `modadd` `modmul` `intmul` `FA` `HA` `div2` `shiftreg` 逐字节相同；
  `dt0`–`dt3` 只差一个空行（pe1 与 pe16 相同）；`modred.v` pe1 缺 CC0 注释头（取 pe4 那份）；
  `modsub.v` pe16 缺 CC0 注释头（取 pe1 那份）。**没有一处是逻辑差异。**
- `rtl/pe1|pe4|pe16/` **暂时保留** —— 它们是折叠度对比表的基线。
  等新树三档验过再决定去留（`research/ref_rtl/` 有上游原件，删了不丢基线）。

### 4.2 参数传递

对外只暴露 `PE_NUMBER`，内部派生 L 并一路传下去：

```
KyberHPMNTT_top #(.PE_NUMBER(16))
  └── KyberHPMNTT #(.PE_NUMBER(16))
        ├── addressgenerator #(.L(L), .TW_ADDR_W(TW))   L = $clog2(128/PE_NUMBER)
        ├── BRAM            #(.ADDR_W(L+1))
        └── BROM            #(.PE_NUMBER(PE), .TW_ADDR_W(TW))
                            ↑ TW = 9/8/7，手工选，**不是** L 的函数（§3.3a）
```

**这是参数化能否成立的关键一环** —— 现在断在这里。

### 4.3 接口：核保持宽，序列化放在核**外**

```
KyberHPMNTT_top #(.PE_NUMBER(16))
  ├── 外部：din[11:0] / dout[11:0]     固定 12 位，三档完全相同
  ├── 中层：序列化 / 反序列化器
  └── 核 KyberHPMNTT                    宽接口 din[12*PE-1:0]
```

选择理由：

- **核的 FSM 一行不用改** —— 风险最小。装载态仍是「每拍写一次 BRAM」，只是拍数回 256
- `PE_NUMBER=1` 时序列化器是**直通**的 → pe1 已验证的时序完全不受影响
- 序列化器能**单独测**
- 换器件时核的宽接口仍在

代价：pe16 装载/读出由 16 拍变回 256 拍。**但 UART 比装载口慢 17,361 倍**，
这点差距淹没在串口里（见 `rtl/H1_port_spec.md` §四）。

### 4.4 参数化后三档的对外行为

| | `din`/`dout` | 装载拍数 | 读出拍数 | `done` = `CC+1` |
|---|---|---|---|---|
| pe1 | **12** | 256 | 256 | 905 / 648 / 905 |
| pe4 | **12** | 256 | 256 | 233 / 168 / 234 |
| pe16 | **12** | 256 | 256 | 70 / 48 / 72 |

接口三档完全一致，只有 `done` 的周期数不同。

## 五、两处 `generate` 分支

### 5.1 PWM2 地址（`PE_NUMBER == 1` vs `else`）

```verilog
generate
  if (PE_NUMBER == 1) begin : G_PWM2_PE1
    // 双读口 + c_pwm 调制，并输出 raddr_b / c_loop_pwm
    raddr    <= (c_pwm < 2) + ((c_loop >> 1) << 1);
    raddr_b  <= c_pwm[0]    + ((c_loop >> 1) << 1);
    waddre   <= ((0 < c_pwm) && (c_pwm < 3)) + ((c_loop >> 1) << 1);
    waddro   <= waddre;
  end else begin : G_PWM2_WIDE
    // PE≥4：数据布局天然对齐，恒等扫描
    raddr  <= c_loop;
    waddre <= c_loop;
    waddro <= c_loop;
  end
endgenerate
```

`raddr_b` / `c_loop_pwm` 在 `PE_NUMBER > 1` 时不输出（顶层的对应通路也走 generate 关掉）。

> **为什么不把 pe1 也改成恒等扫描以消掉分支？** 那会改掉 pe1 已经验证过的数据布局，
> 连带 `refsim/pe1/` 的 KAT 链和 `rtl/H1_port_spec.md` §三 的读出顺序全要重来。
> 收益（少一个分支）远小于代价。**保持 pe1 行为逐拍不变是本次重构的第一约束。**

### 5.2 FSM stall

上游三档的 stall 是手工调的，**不由 L 唯一决定**。本设计不推导新规则，
只把现状逐档编码，保证行为逐拍不变。三档的实际结构（均已核到源码行）：

| | FSM 状态数 | stall 状态 | 每个 stall 停几拍 | 从哪儿进 stall |
|---|---|---|---|---|
| pe1 | 4（2 位） | **无** | — | — |
| pe4 | 6（3 位） | `STL0`→FNTT；`STL1`→INTT | **各 1 拍** | FNTT `S==4`；INTT `S==0`（都在 `c_loop` 扫完那一刻） |
| pe16 | 7（3 位） | `STL0`→FNTT；`STL1`→INTT；`STL2`→INTT | `STL1` **1 拍**；`STL0` / `STL2` **各 2 拍** | FNTT `S<=2`；INTT `S<=2`（→`STL1`）、`S∈{4,5}`（→`STL2`） |

`STL0` / `STL2` 停 2 拍是靠一个 1 位的 `c_stl` 相位计数器实现的
（`rtl/pe16/addressgenerator.v:34,124-134`）：`c_stl==0` 那一拍**冻结全部计数器**，
`c_stl==1` 那一拍执行 stage 推进并放行 FSM。`STL1` **完全不读 `c_stl`**。

⚠️ **pe16 内部还有一处 FNTT/INTT 不对称**：`c_stage` 与 `c_loop` 的 stall 条件**不同**。
INTT 在 `S<=2` 时只冻结 `c_stage`，而 `c_loop` 会回卷、`c_tw` 会递增；
FNTT 在同样位置则三者一起冻结。**这是真的，重构时不要「统一」掉。**

具体每档停在哪个 `c_stage`、进哪个 STL 状态，实现时按上游源码逐条抄写，
由「判据 2：三档 CC 逐拍一致」兜底 —— **抄错了 CC 就对不上，跑一次探针立刻暴露**。
这条判据在这里特别值钱：**stall 结构是三档里最容易抄错的部分**。

## 六、验证策略

按强到弱三层，全部可一条命令复跑：

| 层 | 验什么 | 工具 | 位置 |
|---|---|---|---|
