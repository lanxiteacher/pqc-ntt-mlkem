## 一、先想清楚"什么才算好选题"（决定判断标准）

### 1. "有深度的作品 ≠ 做了一个 CPU"
深度的 4 个真实来源（均**不要求**有 CPU）：
1. **算法/架构加速**——把算法从"软件跑"变成"硬件流水线跑"，给出加速比（近年评奖最对口）
2. **接口/协议工程**——UART/SPI/I2C/以太网/PCIe/JESD204B 等
3. **系统完整度/软硬协同**——把多个子系统拼成能解决真实问题的**闭环**
4. **信号处理链路**——FFT、锁相放大、滤波，把"微弱信号测准"做到极致

CPU 的真实定位：是**学习脚手架**（练状态机/数据通路/总线/访存这套系统思维），也是 **RISC-V SoC**（CPU+总线+外设+能跑真实程序 = 2026 趋势点名的真主流方向）。**裸单周期 CPU ≈ 课程设计，不深。**

### 2. 评委实际上看什么（评分重心）
- **工程完整度**：能上板、能复现、能连续跑
- **资源利用率 + 时序**：LUT/BRAM/DSP 占用、时序报告截图 > 口头"算法高效"
- **实测对比数据**：硬件 vs 软件的加速比、精度、吞吐
- 近年共识：**"能上板演示 > 仿真漂亮"；答辩"能讲明白 > 闷头做出来"**

### 3. 拿奖本质（经验帖浓缩）
> **选对题（结合团队积累）→ 做完整（能上板、能复现、有数据对比）→ 讲清楚（文档/视频/答辩充分展示亮点）**

## 二、本届对"选题"的硬约束（先框死范围再挑方向）

| 约束 | 内容 | 对选题的影响 |
|---|---|---|
| **时间** | 报名 2026-09-22；作品提交约 2026-11-07（**只剩约 2 个月**） | 只选"2 个月零基础能做到能演示"的方向 |
| **队伍基础** | 数电/Verilog **零基础**（没上过板） | 避开需要深厚算法/时序功底的题 |
| **平台** | Zynq-7020，**只用 PL 纯逻辑**（不碰 PS/Linux） | 排除依赖 ARM 生态/Linux 的方案 |
| **打法** | **AI-agent 主力写代码**，人当"架构+验收" | 只选"代码密集高、硬件耦合低"的方向 |
| **心态** | 本届 = **体验局**，为 2027 届打底 | 保底 > 求惊艳：11/7 必须有东西能交 |

### AI-agent 的边界（这是选题的第一过滤网）
- ✅ AI 能帮：生成/改 Verilog、写 testbench 仿真、修逻辑 bug、解释代码、写报告、整理对比数据
- ❌ AI 帮不了：**上板那一步**（引脚约束/时序违例/板不亮）、**实物演示**、**答辩时的理解复述**
- 🎯 **选题口诀：把难度放在 AI 最擅长的"代码"里，绕开 AI 帮不了的"模拟电路 / 高速接口 / 摄像头时序 / 外部仪器联调"**

## 三、AMD 赛道结构对选题的意义

- AMD 赛道近年分两类走法，**报名前必须读官网 2026《选题指南》确认本届划分**：
  1. **命题赛道**（低年级为主）：题目官方给定，省去"选什么题"的纠结，例如 Vitis HLS 命题（信号处理 / NN 加速二选一）——**官方明文鼓励大模型辅助设计，交 Prompt 记录**，最契合本队 AI 打法
  2. **自主选题**：题目自定、器件自选，范围可控 → 可以把作品缩到很小（适合体验局），但题目要自己构思
- 器件范围：AMD 7 系列 / Zynq-7000 / UltraScale(+)。**Versal 只在更高阶综合/高级赛道放开**，本队用不到
- 一旦选定赛道+题目**不可更改** → 选题谨慎，但自主命题的题目范围可写概括，细节 9 月下旬再定

## 五、候选方向逐个细看

### A. 算法硬件加速器（近年评奖审美最对口）
- **做什么**：在 FPGA 用 RTL/HLS 实现某算法的硬件加速单元（FIR 滤波 / 卷积 / FFT-8/16 / 排序网络），CPU 或上位机喂数据，测硬件 vs 软件的**加速比/吞吐/资源占用**
- **AMD 对应**：低年级可直接套 **Vitis HLS 命题**（信号处理 / NN 加速，官方鼓励 AI 辅助）；自主题做独立加速器也成立
- **难度**：中。实现直观（乘加流水线 + 系数 ROM），AI 生成稳
- **为什么适合本队**：纯数字、AI 主场、硬件风险低，且"实测对比数据"正是评委最吃的那套
- **天花板**：高（AI/加速器是 2025–2026 一等奖主力题材）
- **代表作品**：厦门大学·FPGA 智能信号分析（国一，精度≤1%）；各类 CNN 部署作品
- **风险点**：要做到"深"需要体现优化（流水级数、资源复用、量化），纯跑通一个 FIR 深度有限

### B. RISC-V SoC / 软核 CPU（学习脚手架 + 体系结构向）
- **做什么**：Verilog 写 RV32I 小核（约 20 条常用指令，单周期起步）+ 简易 SoC（CPU + BRAM + UART + 寄存器接口），上板跑一段程序（打印→排序/斐波那契），可再接硬件加速器做成"CPU+协处理器"
- **难度**：中。纯代码密集、AI 极擅长；但 CPU 出 bug 时 debug 靠仿真要耐心
- **为什么适合本队**：纯数字、硬件风险低、自带"系统感"；一套工具链（Python 小汇编器转 hex，Windows 别装 GNU 工具链）
- **天花板**：中–高。**裸单周期核不高**，高度来自"做成能跑真实任务的系统 + 讲得出设计取舍 + 软硬协同（接协处理器）"
- **代表作品**：RISC-V SoC 是 2026 趋势点名的三大主流方向之一（需 CPU+外设+真实程序/RTOS）
- **风险点**：Verilog 新手 debug CPU 是体力和耐心的活；范围必须砍小

### C. 图像/视频处理（获奖大户，演示效果最直观）
- **做什么**：摄像头采集 → FPGA 流水线（灰度/去噪/ISP）→ HDMI/VGA 输出；视频缩放、拼接、实时目标检测
- **难度**：中–高。需摄像头驱动 + 时序 + 视频接口，**硬件耦合度明显上升**
- **为什么不太适合本队（今年）**：OV5640/HDMI 的时序和实物联调正是 AI 帮不了、零基础最容易翻车的部分；且 7020 视频方案要外接摄像头模块
- **天花板**：高（每年一等奖大户），2026 趋势"实时风格迁移/视频增强"很热
- **代表作品**：武汉大学·鸟类声音识别偏 AI；北邮·双板多路视频采集识别（紫光同创杯）
- **建议**：作为 **2027 届**方向更合适（先打基础，再用图像题冲奖）

### D. 信号采集 / 仪器仪表（最稳、实物感强、好出完整度）
- **做什么**：ADC 高速采集 → FFT 频谱 → 测幅值/频率/占空比/THD → OLED/LCD 显示；进阶加锁相放大微弱信号检测
- **难度**：中–低。纯逻辑即可完成，不需 ARM 与复杂算法；对 FPGA 新人最友好
- **本队适配**：中。逻辑部分 AI 能扛，但**需要 AD/DA 子板 + 示波器/信号源联调**——模拟部分是 AI 帮不上的
- **天花板**：中。仪器类好演示、报告好写，但差异化要靠精度指标
- **代表作品**：厦门大学·智能信号分析国一；井冈山大学/湖北大学·Mini-LED 分区背光

### E. 高速接口 / 通信（技术壁垒高、卷的人少）
- **做什么**：SFP+/以太网/PCIe/JESD204B 等协议；或 RISC-V SoC
- **难度**：高。吃接口与时序功底 + 需要高速子卡/示波器
- **本队适配**：低（今年）。**强烈不建议零基础碰**
- **代表作品**：三峡大学·多波束高速数字接收机（Zynq-7100，SFP+ 40Gbps）；北理工等

### F. 端侧多模态感知融合（2026 新主流，天花板高）
- **做什么**：摄像头+麦克风/雷达等**多传感器**在同一 FPGA 上实时融合推理
- **难度**：高。需软硬协同 + 较强平台 + 算法背景
- **本队适配**：很低（今年）。留给 2027 届有基础后考虑
- **趋势来源**：2026 FPGA 大赛作品趋势分析点名"端侧多模态感知融合成主流"

## 六、近年趋势与获奖规律（2025–2026）

- **三大主线**：端侧 AI、国产化、边缘化
- **评委偏好的技术点**：硬件加速 + 低功耗 + 资源利用率 + 混合精度量化
- **获奖作品共性**（反复验证）：
  - 多与**图像/AI 加速**相关（FPGA 优势领域）
  - 强调**软硬协同**（Zynq 异构、CPU+加速器）
  - **创新点落在"硬件加速"或"低功耗实现"**上
  - 报告呈现**资源占用表 + 时序报告 + 加速比/精度对比**
- **获奖者共识的误区**：仿真漂亮但上板翻车的项目走不远；"你能做出来 ≠ 你能讲明白"

## 七、选择方法论：怎么把范围收窄

### 评估清单（每候选方向过一遍）
1. 能找到往年同类获奖作品吗？（证明做得到 + 评委认可）
2. 看完"要做什么"，心里是有底还是发怵？
3. 需要的外部硬件/仪器（摄像头/AD-DA/示波器/高速子卡）能不能借到？
4. 有老师懂这个方向能指导吗？
5. 这个方向近年热度/获奖密度如何？

### "五问过滤法"（从候选 → 锁定）
- **问①**：AI 把代码全写了之后，剩下来要我自己搞定的部分，我搞不搞得定？
  - 答"搞不定"（如模拟调试/摄像头时序/高速接口）→ 先放下
- **问②**：2 个月内能上板能演示吗？
- **问③**：做完能写出"完整度+对比数据"的报告吗？
- **问④**：评委问到原理，AI 讲给我、我能复述吗？
- **问⑤**：这个方向能不能成为 2027 届继续深挖的起点？（体验局要"一步一脚印"）

### 决策时间表
| 时间 | 要做的事 |
|---|---|
| 9/22 前 | 落实板卡 → 读 2026 AMD《选题指南》→ 报名（锁赛道 + 概括性题目） |
| 9/22–10 月中 | 把选定方向的题目细化 + 搭工程骨架 |
| 10 月中–10 月底 | 实现 + 上板 |
| 11 月初–11/7 | 写报告 + 录 5–10 分钟演示视频提交 |

## 八、与"本队匹配度"的当前倾向（供讨论，非定稿）

综合"零基础 + 2 个月 + AI 主力 + 体验局 + 想要高度"：

- **推荐倾向**：以 **B（软核 CPU/SoC）做脊梁**，把 **A（算法加速器）** 作为增量，做成 **"RISC-V SoC + 硬件协处理器（FIR/点积）"** 的软硬协同作品——CPU 保底完整度，加速器提供"算法硬件化 + 对比数据"的亮点，恰好覆盖评委最吃的前三件事。
- **风险分档**（保底思维）：CPU 完整跑通 → 已有可提交作品；CPU 卡住 → 退到"简化 CPU + 小程序"，保证有东西交。
- 若 9/22 前读官方命题发现 Vitis HLS 命题赛道更省心（低年级可用），可优先走命题，省去自主选题的构思成本。
