【0】结论先行（只读这一段也够）
--------------------------------------------------------------------------------
  问：有哪些"开源、轻量、适配"的防抖代码可以直接用？

  答：**端到端的防抖代码，一个都没有。**

      GitHub 全站实测：
        · "video stabilization fpga"      → 2 个仓库（均 0 星，与 EIS 无关）
        · "image stabilization verilog"    → 0 个仓库
        · "electronic image stabilization" → 3 个仓库（全是 PC 端 MATLAB/Python）
      这不是搜索姿势问题，而是"这类代码基本不存在"。

  但是 —— **"没得抄"不等于"做不成"，原因有三**：

    ① 你们 L1 阶段要用的"灰度投影法"极其简单（就是一堆加法器），
       **自己写比读懂别人的 SAD 代码还快**。它不是那种需要抄的复杂东西。
    ② 能借到的是"零件"而不是"整机"：有 2 份 **MIT 协议的块匹配运动估计 RTL**，
       质量不错，适合**当范本读**（学 RTL 怎么组织、testbench 怎么写），
       但架构是 H.264 视频编码风格，**不能直接搬去做稳像**。
    ③ 你们真正缺的不是 GitHub，而是**厂商例程**——那才是 L0 的地基，
       而它恰好缺失（见【4】）。

  ★一句话：**这个选题的"防抖"部分注定要自己写。这不是坏消息——
    它正是你们答辩时"哪些是我们做的"最硬的答案。**

--------------------------------------------------------------------------------
【1】先分清"要借哪一层"——三层需求，来源完全不同
--------------------------------------------------------------------------------
  做 EIS 需要三样东西，它们的开源可获得性差异极大：

    第①层  L0 平台通路（摄像头→VDMA→DDR→HDMI 出原图）
           → 需要"能跑通的工程"。**开源可得性：差**（厂商例程最合适，但你们没有）
    第②层  运动估计（算 dx,dy）
           → 需要"算法 + RTL"。**开源可得性：中**（有 MIT 块匹配 RTL，是零件）
    第③层  运动补偿 + 平滑（挪窗口 + 滤波）
           → 需要"地址偏移读取逻辑 + PS滤波"。**开源可得性：极差**（几乎无人开源）
             ★但它是你们全队技术风险最大处，也是最"自己写"的部分。

  后面【2】评的是第②层，【3】评的是①③层的替代来源，【4】说你们真正的缺口。

【2】运动估计（第②层）开源零件评估
--------------------------------------------------------------------------------
2.1 ★首选范本：yigitbektasgursoy/Motion_Estimation_Hardware_Verilog

    地址     https://github.com/yigitbektasgursoy/Motion_Estimation_Hardware_Verilog
    语言     Verilog（纯 RTL，非 HLS 生成物）
    协议     **MIT**（可自由使用/修改/商用，最友好）
    热度     ★13，最后更新 2024-06
    目标板   Nexys-A7-100T（Artix-7）—— **不是 Zynq，但纯 RTL 可移植**

    规格     搜索窗 31×31，参考块 16×16，16 个处理单元(PE)，31.25 MHz

    文件结构（实测清单，分层清晰）：
      rtl/MotionEstimationTop.v     ← 顶层
      rtl/ControlUnit.v             ← 控制
      rtl/Datapath.v                ← 数据通路
      rtl/ProcessingElements.v      ← SAD 计算（核心）
      rtl/InstantMinComp.v          ← 找最小 SAD
      rtl/MinTrackerComp.v          ← 最小 SAD 跟踪
      rtl/ReferenceBlockMemory.v    ← 参考块存储
      rtl/SearchWindowMemory.v      ← 搜索窗存储
      testbench/ME_tb.v             ← 仿真激励
      testbench/testcase/*.txt      ← 测试数据
      testbench/testcase/min_SAD.py ← **Python 参考模型**（可对比硬件结果）
      testbench/testcase/randblock_gen.py ← 测试数据生成脚本
      constraint/Constraint.xdc     ← 引脚约束
      docs/report.pdf               ← 设计报告

    ★为什么它值得看（即便不用）：
      · 它示范了"一个视频类 RTL 模块该怎么分层"——顶层/控制/数据通路/存储分开，
        这正是甲写运动估计时该模仿的结构。
      · 它带 **Python 参考模型**：先用 Python 算一遍理论最小 SAD，再和 Verilog
        仿真结果对比。**这个"软件出标准答案 → 硬件对齐"的验证方法，
        是甲做仿真验证的最佳范式，值得直接照搬到投影法上。**
      · 它有完整 testbench + 测试数据，是很好的仿真入门样板。

    ▲为什么**不能直接搬来做稳像**：
      · 它的目标是视频编码（H.264）的块匹配，假设"每个宏块独立运动"，
        输出的是**每块的局部**运动矢量；而稳像需要的是**整幅画面的全局**运动矢量。
      · 它的接口是内存读写式（一次性喂入整块数据再算），不是**逐像素流式**，
        和你们"摄像头像素流实时处理"的链路不匹配，改造量很大。
      · 16 个 PE + 31×31 搜索窗对 Zynq-7010 偏重（7010 只有约 17.6K LUT），
        若板子是 7010 需大幅裁剪。

    → 建议用法：**当作"结构范本 + 验证方法范本"来读，不要当库来移植。**

【3】平台通路（第①③层）的来源评估
--------------------------------------------------------------------------------
3.1 失败的候选：ZedBoard 视频流水线工程（原以为最有用，实测打折）

    ugoleone/zedboard_image_processing_pipeline
      ZedBoard = Zynq-7020，芯片与你们一致；camera→TPG→filter→VDMA 结构对口。
    ▲但实测结果令人失望：
      · 全仓 949 个 .v/.vhd 文件中，**绝大多数是 HLS/Vivado 自动生成的中间产物**
        （路径里满是 `solution1/impl/ip/hdl/...`、`project.cache/...`），
        不是人写的可读源码。
      · **无协议**（法律上不能直接用）；159 MB，最后更新 2020 年。
      · 它本身是 **HLS 路线**的产物——而你们的方案已明确"砍掉 HLS"。
    → 结论：**参考价值有限，不推荐作为地基。**

3.2 其它同类（都不理想）

    squid55/Arty-Z7-OV7670-HDMI    VHDL，★0，2026。Arty Z7 也是 Zynq-7020，
                                  摄像头→HDMI 结构对口，但 **VHDL 语言与你们不符**，
                                  且 0 星、无社区验证。
    MysEcho/Dynamic-Image-Processing-on-Zynq   ★3，HTML 为主
    santi-rwx/Binocular-Stereo-Vision-over-FPGA  VHDL ★2
    selaka-deemantha/Embedded_Linux_Video_Pipeline_on_Zynq_SoC  VHDL ★2（且是 Linux 路线，已砍）

    ★规律：**FPGA 视频工程开源生态以 VHDL 和 HLS 为主**，而你们学的是 Verilog、
      且已决定不走 HLS。这进一步说明"照抄"这条路对你们不成立。

3.3 ★对我上一份报告的更正（请以本条为准）

    在 `选题分析_高帧率视频防抖.txt` 的【5.1】里，我把
    `IMS-AS-LUH/zynq-stewart-platform` 列为"最值得先看的一份代码"。**现更正如下：**

      · 实测：★3，**无协议**，63 MB，GitHub 标注主语言为 **Ada**，
        含 VHDL 模块（crop_stream.vhd / histogram_projection.vhd），最后更新 2024-07。
      · **更关键的实质问题**：它是 **Stewart 平台（机械云台）稳定**项目
        —— 属于"路线B 机械防抖"，**不是你们要做的"路线C 电子稳像(EIS)"**。
        里面的 crop_stream / histogram_projection 只是它的辅助模块，
        不能据此认为"拿到了 EIS 代码"。
     → 结论：**降级为"可读思路、不可用代码"**。抱歉，上一份报告此处判断偏乐观，
       本次已按实证修正。

【4】★你们真正的缺口：不是 GitHub，是厂商例程（必须尽快解决）
--------------------------------------------------------------------------------
  实测项目目录状态：
    · `4_Source_Code/` **实际为空** —— 唯一文件是 332 MB 的
      `6_Embedded_Qt_Design.zip.baiduyun.p.downloading`（百度网盘下载残件）
    · 也就是说：**OV5640 采集 / VDMA / HDMI / RGB-LCD 这些 L0 地基例程，
      你们手上一个都没有。**

  这件事比"找不到开源防抖代码"严重得多。原因：
    · 第【3】节已证明，GitHub 上没有能替代厂商例程的干净 Verilog 视频通路工程；
    · 而 EIS 的 L0（先让摄像头画面稳定显示到屏幕）**必须**先跑通，
      乙的进度就是全队进度，它卡住则整队卡住；
    · 开源件（【2】的 SAD 范本）都要等 L0 通了才有意义。

  → 行动（最高优先级，早于任何技术学习）：
      1. 到正点原子下载中心补齐源码包：
         http://www.openedv.com/docs/boards/fpga/zdyz_linhanz(V2).html
         或论坛 www.openedv.com/forum.php（找"资料下载"）
      2. 需要的具体例程：OV5640 摄像头采集、VDMA 视频传输、RGB-LCD/HDMI 显示、
         I2C(EEPROM) 读写（配摄像头用同一套协议）
      3. 记住硬约束：**工程必须放纯英文路径**（如 C:\fpga\），
         项目根 `FPGA 2026` 含空格和中文，不能直接在里建 Vivado 工程
      4. 同时补 B 盘开发工具（Vivado/Vitis）、C/D 盘视频教程

【6】三条结论
--------------------------------------------------------------------------------
  1. **端到端防抖代码在开源界不存在**（GitHub 实测 0~2 个不相关结果）。
     不要把时间继续花在"找现成代码"上——**这个搜索已经做完了，答案是"没有"。**

  2. **能借的是"范本"和"零件"，不是"整机"**：
     · 运动估计：2 份 MIT 协议的 Verilog 块匹配实现，当**结构范本 + 验证范本**读；
     · 平台通路：开源替代品实测均不合格（HLS 生成物 / VHDL / 无协议），
       真正该用的是**厂商例程**——而它当前缺失。

  3. **最紧急的动作不是学技术，是补齐厂商例程**。
     A 盘源码为空是目前最大的单点阻塞，早于所有技术学习。

  ★对你们其实是好消息：
    既然没有现成代码可抄，那么"运动估计硬件化 + 补偿窗口逻辑 + 平滑策略"
    这三块必然出自你们之手 —— 答辩问"哪些是你们做的"，答案非常硬。
    这比"跑通了厂商 demo"有说服力得多。

【附】如何自己复查（方法留给你们，以后不用依赖我）
--------------------------------------------------------------------------------
  在浏览器直接搜索（比 Google 更准）：
    https://github.com/search?q=video+stabilization+fpga&type=repositories
    https://github.com/search?q=image+stabilization+verilog&type=repositories
  或用命令行（需装 gh）：
    gh search repos "video stabilization fpga"
  筛选要点：① 看语言是不是 Verilog/VHDL；② 看有没有 LICENSE；
            ③ 看有没有 .v/.vhd 与 testbench（而非全是 HLS 生成物）；
            ④ 看最后更新年份（超过 3 年慎用）。
