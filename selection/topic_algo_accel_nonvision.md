## 〇、为什么重筛 & 锁定的前提

- **被回退的原因（队长意见，2026-09-09）**：上一批三选一（实时去雾 / HDC视觉分类 / ORB稳像）全是图像/视觉，默认依赖摄像头——"算法硬件加速方向不一定非用摄像头"。重筛硬条件：**候选不得是图像/视觉方向**。
- **载体**：PC 上位机跑同一算法（C/Python）计时作 CPU 基准 → 同输入经串口/USB 喂给 FPGA → FPGA 加速计算 → 结果回传 PC，对比正确性 / 吞吐 / 延迟 / 能耗。
- **硬件红线（沿用）**：XC7Z020（7020）= 53,200 LUT / 220 DSP / 140×36K BRAM ≈ **4.9Mb（≈0.6MB）片上存储**。
  - ✅ **2026-09-18 已解决**：领航者底板的 USB-UART **不是焊死在 PS 上的**，有 **P5 跳线排针**在 PS/PL 之间二选一（**PL 档 = 3–5、4–6 短接**）。另有 4 条零/低成本退路（40PIN 扩展口 + 3.3V USB-TTL 小板 / RS232 / ATK 模块口 U4 / RS485）。**→ 上板唯一硬件点风险已从"未知"降到"几乎为零"。**
  - ⚠️ **但要注意真瓶颈换了地方**：不是接不上，是**串口带宽比计算核慢 3–4 个数量级**（115200 波特 = 2,880 样本/s）。必须用"片上激励源测内核吞吐 + 串口另走正确性对拍"的架构，详见可行性分析第三节分水岭 1。
- **一个必须接受的现实（贯穿全部候选）**：
  > 脱离"实时视频 + 帧率对比"这个直观基准后，"快多少倍"的叙事本来就弱一档。**非视觉题的卖点叙事要换成评委更吃的：吞吐（样本/s）、单样本延迟、能效（每样本 μJ/W）、资源占用表。**
  > 且 2025 热门的"新范式"方向（PQC / SNN / HDC 等），**"FPGA vs CPU"的干净倍率大多没有现成公开数据，必须自己在 7020 上测出来才算数**。
- 队员偏好（沿用）：**新算法优先、接受难实现**；本届定位体验局（保底 = 11/7 有东西能交）；PL-only；AI-agent 主力写代码。

## 一、候选 A：后量子密码（PQC）—— ML-KEM 多项式乘法 / NTT 加速

### 是什么
量子计算机威胁 RSA/ECC → 美国 NIST 于 **2024-08 正式发布抗量子标准 ML-KEM（即 Kyber）与 ML-DSA**。ML-KEM 每一轮核心热循环是**多项式乘法**，工程实现用**数论变换 NTT**（256 点，模数 q=3329）把乘算降到 O(n·log n)。FPGA 上做一个 NTT/INTT 蝶形计算阵列 + 模约减单元，即可把"软件里最贵的一段"搬进硬件。

**Scope 分两档（强烈建议量力选小档）**：
- **小档（推荐起点）**：纯 NTT/INTT 加速核。PC 喂多项式系数 → FPGA 算 NTT → 回传；正确性直接对照官方参考实现与**标准测试向量 KAT**（PQC 圈有现成判据，比多数 AI 题更容易验证）。再往上走一步 = 把 keygen/encap 的数据通路在硬件搭出来，与 CPU 整套流程比吞吐。
- **大档**：完整 ML-KEM-512 协处理器（keygen/encap/decap）。体验局不推荐一开始就冲这档。

### 对比对象（这批候选里最"权威"）
- 官方 **pq-crystals/kyber C 参考实现**（跑在 PC 上）就是现成的 CPU 基准；软件 Kyber 出名地慢（软件 NTT 的模约减极繁重）。
- 正确性有 **KAT 标准测试向量**可对拍 → 报告里"硬件结果 = 官方参考结果"是硬证据。
- 旁证：GPU 侧 NTT 加速报 **32× vs CPU**（IEEE 2025）；RISC-V SoC 集 NTT 加速器比 C 参考省 **37%–56% 总运行时间**（Electronics 2026）。**FPGA-vs-PC 的干净倍率要自己在 7020 测**（大概率可观，因为蝶形阵列可全并行、跑到板卡主频）。

### 为什么"新"且值得
- 2024-08 才定标 → 2025–26 FPGA 加速论文**井喷**（搜索结果一屏都是），属国策级"必须硬件化"的方向。
- 答辩"为什么是 FPGA / 为什么不用 ARM"有标准答案：**软件实现有侧信道（时序/功耗泄露密钥）风险 + 吞吐不够 → 硬件加速 + 常量时间实现是刚需**。这个叙事比"我加速了 XXX"硬得多。

### 7020 适配与资源
**⚠️ 修正（2026-09-18）：局部极好，但"全展开"是陷阱。**
- 存储确实不是问题：单次 256 点 NTT 中间态约 256×12bit ≈ 几 KB BRAM（0.6MB 绰绰有余）。
- **但 256 点 NTT = 8 级 × 128 蝶形 = 1024 个蝶形单元，每单元一个模乘 → 需 1024 个 DSP，220 个装不下。必须做时分复用/折叠**（如 64 或 128 路并行），配合存储体分组与地址生成。
- ✅ **7020 上有真实先例**：PYNQ-Z1 (XC7Z020-1) 上完整 ML-KEM 实测 33,733 LUT (63%) / 151 DSP (69%) / 23.5 BRAM (17%) / 100 MHz，encap 5.01 ms、decap 2.24 ms。手写 RTL 路线可省到 ~23% LUT（UniPAM：12k LUT / 4 DSP / 9 BRAM）。**不是首作冒险。**
- 真正的卡点不在资源，在 **q=3329 的模约减正确性**（AI 最容易"几乎写对"的地方）+ **"快多少倍"叙事弱**（官方参考 C 已优化；真正卖点是**常量时间抗侧信道**）。

### AI 代工边界 / 人扛点
| 环节 | AI 能帮？ | 备注 |
|---|---|---|
| 蝶形单元、旋转因子 ROM、地址生成 | ✅ 主场 | 纯逻辑 + FSM，AI 稳定输出 |
| q=3329 的模约减/负数处理（定点） | ✅ 能写 | 数值优化 AI 强项；务必对拍参考实现 |
| KAT/参考 C 验证脚本 | ✅ 写脚本 | 你只需会跑 |
| 理解"NTT 为什么替掉朴素乘法"到能复述 | ✅ AI 讲给你 | 你要过算法概念关（约半天的学习量） |
| 上板 UART 喂数/回传 | ❌ | 简单串口，比摄像头时序简单一个数量级 |

### 难点与风险 / 回退
- 风险 a：模算术正确性（负值、进位、位宽截断）要仔细——**对策 = 每步对拍官方参考，别直接上板**。
- 风险 b：工程量若冲"完整 KEM"会涨 → 砍到 NTT 核 + encap 数据通路即可。
- 回退：只交"纯 NTT/INTT 核 + 与 CPU 参考的吞吐/延迟对比表 + KAT 正确性"也是完整的"算法硬件加速 + 实测对比"作品。

**一句话**：本批里最"新"、最有辨识度、对比对象最权威（官方 KAT），答辩说服力最强；代价是难度中高、要量力砍 scope。

## 二、候选 B：储层计算 ESN（回声状态网络）时序预测加速

### 是什么
脑启发轻量递归模型：输入时序 → 送进一个**权重随机且固定**的循环"水库（reservoir）"→ 只训练一层线性读出。因为水库不动，训练极轻、硬件只做前向。典型任务：混沌系统 / 金融 / 传感器时序的**预测或分类**。

**Scope**：PC 端离线训练输出层（numpy，AI 全包）→ 导出水库结构 + 读出权重 → FPGA 做水库前向（可量化/二值化 → 乘加树甚至移位）→ 对 PC 喂来的流式样本逐点实时预测，回传 PC 画预测 vs 真值曲线。

### 对比对象与已公开证据
- 你自测：PC（numpy/C）跑同尺寸 ESN 逐样本计时 vs FPGA 吞吐/单样本延迟/能耗。
- 已公开的强数据（**对比硬件实现而非 CPU**，可当"能达到的量级"参考）：
  - Paderborn 2025 流式 ESN：**最高 188 Megasamples/s 吞吐、5.3ns 延迟**；DSP 版与纯 LUT 版均有；
  - 同组框架用压缩+量化：**资源省 12×、能耗省 10×**；
  - 金融时序 ESN on FPGA（KCU105）：**0.68W 功耗、83.5 MHz**。
  - 来源见文末。→ vs CPU 的倍率仍要自测，但这类"100 Msps 级吞吐"数字一旦测出，展示力不输 43×。

### 为什么值得
- 边缘低功耗轻量模型是 2025–26 热题，FPGA 落地研究比 CNN/LLM **少得多**；代码结构规整、对 AI 极其友好。
- 能耗/吞吐叙事正好命中评委偏好的"资源利用率 + 能效"。

### 7020 适配与资源
**✅ 四家里余量最大**（判断成立并加强）。二值/量化水库可 **LUT-only**（乘法→加/移位），几乎不吃 DSP/BRAM；压缩版实测仅 **4.6K LUT**（8-bit、N=149），余量 ~90%。
- ⚠️ **但"必须量化"是硬约束**：未量化的 32-bit 直接逻辑需 **160 万 LUT，任何 7 系列都装不下**。8-bit 是入场券。
- ⚠️ 文献那批漂亮数字（188 Msps / 5.32 ns）**器件型号普遍未标明**、水库规模也没说清，**别当承诺**。

### AI 代工边界
| 环节 | AI 能帮？ | 备注 |
|---|---|---|
| 水库矩阵生成 + 输出层训练（PC/numpy） | ✅ 全包 | 你要理解"只训输出层"这概念 |
| FPGA 前向（乘加树/移位 + 状态更新） | ✅ 主场 | 规整流水线 |
| 数据生成、回传画图脚本 | ✅ | 你跑通即可 |
| 上板串口 | ❌ | 简单 |

### 难点与风险 / 回退
- 主风险：任务/数据要造得"演示友好"（预测曲线要肉眼可见地准）；精度要调（水库规模、位宽量化）。
- 回退：退化到"离线喂一批序列、批量算、比吞吐"也能交。

**一句话**：公开数字最漂亮、资源最省、代码最规整、上板风险低；弱点是"算法新"不如 PQC/SNN，答辩要主动讲**吞吐/能耗/边缘部署**优势，别被"这不就是 RNN"问住。

## 三、候选 C：SNN 脉冲神经网络 —— 生物信号（ECG/EEG）分类

### 是什么
神经形态/事件驱动网络：神经元只在膜电位过阈值时发**脉冲（spike）**，信息在脉冲时序里；硬件只需加法/比较（无乘法），天然低功耗。**做非视觉任务**：ECG 心律分类（MIT-BIH 公开库）、EEG 癫痫检测，或任意 PC 喂的流式特征序列二分类。

**Scope**：PC 端离线训练（snnTorch / Brian2 等现成库）→ 导出脉冲编码 + 权重 → FPGA 前向推理 → PC 喂流式样本、FPGA 逐窗输出分类。

### 对比对象与已公开证据
- 你自测：PC 跑同 SNN（或跑达到相近精度的传统 DNN）vs FPGA 推理 → 比**吞吐 / 每样本能耗 / 延迟**。
- 已公开（注意多在**大芯片** ZCU102 / xc7z045 上，只当叙事佐证，**7020 要自己缩小收敛**）：
  - ECG 检测 SNN 处理器（xc7z045）：91.4% 精度、**62 mW**、215 μJ/次分类；
  - 可穿戴癫痫检测（ZCU102）：98.1% 精度、**3.73 μJ/次**。
  - 来源见文末。

### 为什么值得
- "生物信号 + 神经形态 + 可穿戴低功耗"是 2025 大热且辨识度极高的方向，评委眼缘好；能耗数字（μJ 级）非常"上台面"。
- 比 ESN 更像"新一代"（脉冲/事件驱动叙事）。

### 7020 适配与资源
**⚠️ 修正（2026-09-18）：不能想当然——DSP 是硬约束，取决于架构选择。**
- **反例**：有人在 **PYNQ-Z2（就是 7020）**上实测的 QCSNN，**220/220 个 DSP 打满 + BRAM 吃掉 67%**。这是四家里唯一"刚好装下、没有余量"的案例。
- **正例**：Spiker+/Carpegna 那一路特意做成 **DSP=0**（7.6k–18.3k logic cells + 18–51 BRAM），余量就出来了。
- → **若选 C，一开始就必须定 DSP=0 架构**（膜电位积分用条件加/移位，不用乘法器），否则 DSP 打满后无路可退。
- 另一难点：公开的强结果多在 XC7Z045 / ZCU102 / iCE40 上，**缩到 7020 保精度要自己收敛**（FPGA SNN 的 ECG 精度普遍落在 83%–99%）。

### AI 代工边界 / 人扛点
| 环节 | AI 能帮？ | 备注 |
|---|---|---|
| 离线训练 + 脉冲编码 + 权重导出 | ✅ | 用现成库，AI 全会 |
| FPGA 前向（膜电位积分 + 阈值比较） | ✅ 主场 | ⚠️ **原判"逻辑简单"已修正**：逻辑单元确实简单，但**资源是否省取决于架构选择**——见过 7020 上打满全部 220 DSP 的实测。必须按 DSP=0 架构设计 |
| 数据集下载/灌入/标签处理 | ✅ 写脚本 | 公开库可直接下 |
| **理解脉冲时序编码（时间窗/不应期/膜电位）到能复述** | AI 讲给你 | **本项目最大学习门槛**，请预留半天~一天 |
| 上板串口 | ❌ | 简单 |

### 难点与风险 / 回退
- 主风险 a：时空编码概念门槛是三家里最高（比 ESN 的"水库"难讲）——对"答辩要能复述"压力大。
- 主风险 b：要把大芯片方案缩到 7020，需自己收敛规模与精度。
- **回退链**：若 SNN 卡在理解/缩版上，同一套"流式信号分类硬件"骨架**退到候选 B（ESN）**只换推理模型 → B/C 天然是一条降级链，这是选 C 的最大安全感来源。

**一句话**：最新、最性感、能耗叙事最好，但学习门槛与缩版成本是三家里最高；适合"想冲新范式、但已接受用 B 兜底"的队伍。

## 四、候选 D：HDC 超维计算 —— 非视觉分类（文本/传感器流）

### 是什么
把被打回稿里"HDC 视觉分类②"的视觉壳子剥掉：输入特征编码成**高维二值超向量**，与各类原型向量比**汉明距离/相似度**分类。非视觉任务任选：
- **文本情感/主题分类**（PC 喂分词/编码后序列）；
- **传感器流异常检测**（周期性正常 vs 异常）；
- 惯性/手势序列分类（数据来自 PC 仿真或预先采集）。

**Scope**：PC 离线把训练集编码、累加出各类原型 → 把编码规则烧进 FPGA → FPGA 对每条新样本现场编码 + 比相似度 → 回传分类标签。逻辑只有 **XOR / 多数投票 / 移位 / 计数**，几乎零乘法。

### 对比对象
- 你自测：PC 跑 HDC（Python）vs FPGA，比吞吐/能耗/延迟。**7020 无公开数据，必须自测**（这是 HDC 老话，但 7020 上大概率可观：运算极轻且高度并行）。

### 为什么值得
- 保留"新范式 + 7020 首作"差异化（GitHub 有 Zynq AXI-HDC 加速器 IP 可参考/二次开发），同时**从原②改造量最小**——是最快能落地的"新算法"选项。

### 7020 适配与资源
**⚠️ 修正（2026-09-18）：LUT 极省，但 BRAM 才是瓶颈。**
- 反直觉的一点：BIHDC 在 **D=10K 全二值**时，LUT 只吃 **17.5%**、DSP 只用 **1 个**，却啃掉 **102/140 BRAM（72.7%）**。**这是四家里 BRAM 最紧的。**
- 两条出路：**降 D**（D=256 时只要 1,257 LUT / 1 BRAM，余量巨大）；或走**"用 LUT 换 BRAM"的二进制路线**（F5-HD 在 Kintex 上是 82% LUT + 5% BRAM，与 BIHDC 完全相反的取舍——**7020 正好是 BRAM 紧、LUT 松，这条可能更合适**）。
- ✅ 亮点：**7020 上没有任何论文给出"post-PAR + 板上实测功耗 + 全套资源 + 吞吐 + 精度"的完整数据**——你测出来就是首作，对竞赛是加分，但要自己扛风险。

|---|---|---|
| 编码规则设计 + 原型训练（PC/Python） | ✅ 全包 | 你要理解"编码-捆绑-相似度"三概念 |
| FPGA 编码 + 汉明距离单元 | ✅ 极擅长 | 逻辑最简单的一组候选 |
| 数据流/回传 | ✅ | |
| 上板串口 | ❌ | 简单 |

### 难点与风险 / 回退
- 主风险：**演示直观度最低**（"分类对了"只是串口回传一个标签/PC 画条曲线）；答辩易被问"为什么不用 DNN/CNN"。
- 回退：与 PC 端一个小 DNN 做**"同任务、资源与功耗对比"**，把叙事从"快多少倍"转向"省多少资源做到接近精度"。

**一句话**：最稳最简、逻辑最小、最快能做完并贴上"新范式"标签；代价是演示最"平"，适合"想保底又要 '新' 标签"的队伍。

## 五、经典对照组（明确标注：非新，仅当"倍率震撼"备胎）

若最终放弃"新算法优先"，要"倍率震撼 + 无摄像头"的经典款还有两个（研究老、做的人多，不推荐为首选）：
- **Smith-Waterman 基因局部比对**：经典脉动阵列，公开 **>100× vs CPU**，数据 PC 喂短序列，对比超直观；缺点 = 算法老、不"新"。
- **Monte Carlo 期权定价**：公开 **~22× vs CPU**，随机数生成 + 路径并行，金融叙事清晰；倍率中等。

（通用 FFT/卷积/排序核不算——太"课程设计"，深度不够。）

## 七、共同的"CPU 对比 + 演示"做法（无摄像头版）

1. **同一份输入**（同一批多项式 / 同一段时序 / 同一批样本）分别喂给：
   - **PC 软件**：C 或 Python 实现同一算法（PQC 用官方参考 C；其余自写），逐批计时；
   - **FPGA**：硬件流水线/阵列，测吞吐、单样本延迟、功耗。
2. **正确性**：PQC 对拍官方 KAT；其余与 PC 端结果逐点对拍（相对误差/精度）。
3. 输出一张对比表：吞吐（样本/s 或 NTT/s）、单样本延迟、功耗、能效（/W）、资源占用（LUT/BRAM/DSP + 时序报告）→ 即评委最吃的那套。
4. 数据流：**PC →（USB-UART/串口）→ FPGA →（回传）→ PC 显示/画图**；板级只有这一条简单链路，无摄像头/HDMI 时序包袱。
5. ⚠️ **加一条（2026-09-18 补，很重要）：串口带宽是共同天花板，架构上必须绕。**
   - 115200 波特（8N1）= 11,520 字节/s → 4 字节/样本时端到端**上限仅 2,880 样本/s**；板载 CH340 上限约 2 Mbps（≈5 万样本/s）；外接 FT232H 走 40PIN 可到 3–12 Mbps。
   - 对照：ESN 文献吹 188 Msps；PQC 一个多项式 384 字节走 115200 要 33 ms，而 FPGA 3.4 µs 就算完。**链路比计算核慢 3–4 个数量级。**
   - **解法（学术界标准做法）**：① **片上激励源**（FPGA 内用 LFSR/ROM 自生成测试向量，只回传校验和+少量结果）→ 测**内核吞吐**；② **正确性另走一路**（少量向量慢慢过串口逐点对拍，PQC 直接对 KAT）；③ **两个数分开报**（内核吞吐 + 端到端吞吐并注明链路速率）。
   - 不提前设计，会在 10 月底才发现"演示数字出不来"。
