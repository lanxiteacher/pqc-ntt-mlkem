# 工具链与上板

## 1. 仓库路径里的撇号会让综合引擎崩掉

**现象**

Vivado 的综合引擎 ABC 报出**看不懂的错**，或者悄悄读到**错误的文件内容**。
路径里有个 `'`（本机是 `C:\Users\l'x\Desktop\...`）。

**原因**

Vivado 内部会**拼一个 shell 命令行**去调 ABC，路径里的撇号**提前闭合了引号**，
后面的字符被当成命令的一部分。
（症状是「路径里的 `l'x` 变成了 `lx`」。）

⚠️ **这条在两条路上都成立**：综合引擎，以及 `hw_server`（烧录那条路）。

**怎么修**

**一律从仓库外的干净目录启动 Vivado**，源码用**绝对路径**传进去：

```bash
cd /c/fpga_work          # 仓库外，路径不含撇号
vivado -mode batch -source /path/to/script.tcl
```

**怎么预防**

⚠️ **在仓库目录里直接用 Vivado GUI 建工程同样会中招。**
新建工程的目录**永远不要含空格、中文、撇号**。
（这也是「路径别含中文/空格」那条通用建议的来源 —— 但**撇号更隐蔽**，
它不是「不推荐」，是**会真的出错**。）

**谁扛**：人

## 2. 综合子进程间歇性报「文件读不到」

**现象**

Vivado 2020.2 的综合 helper 子进程**间歇性**报某个文件读不到。
**报错的对象随机漂移**，而且那个文件**确实存在**。

**原因**

工具本身的抖动，不是你的文件有问题。
（用主进程做了 1180 次 I/O 探针，**0 失败** —— 说明文件系统没问题。）

**怎么修**

脚本带重试（3 次足够）。

**怎么预防（这条最关键）**

⚠️ **重试之前必须先删掉本轮要重写的报告。**
否则上一轮的**旧报告**还在，会让「失败」被误判成「成功」——
脚本以为跑完了，其实跑的是上一次的产物。

**怎么发现的**

「同一份源码两次跑出不同的错误」+「报错的文件明明存在」，
这两个现象摆在一起就不是你的问题。

**谁扛**：人

## 3. 串口号会变，不要写死

**现象**

文档里写着「串口是 COM10」，实际跑起来**连不上**。

**原因**

Windows 按「**插在哪个 USB 口**」现分配 COM 号，**换个口就变**。
（实测 `GetPortNames()` 里根本没有 COM10 —— 那是条状态 `Unknown` 的**幽灵条目**；
设备实际枚举为 COM9。）

**怎么修**

按**设备名**找，用前现查：

```powershell
[System.IO.Ports.SerialPort]::GetPortNames()
Get-PnpDevice -FriendlyName "*CH340*"     # 按设备名确认
```

**怎么预防**

**文档里写「设备名 + 用前现查」，不写具体端口号。**
板载 USB 转串口芯片的型号（例：CH340C）比 COM 号稳定得多。

**谁扛**：人

## 4. 上板的三个物理前置条件（少一个就是「没反应」）

**现象**

程序烧进去，串口**收不到任何东西**。没有任何报错。

**原因**

板上三条硬前置没满足：

| 前置 | 怎么设 |
|---|---|
| **启动模式拨码** | 拨到 **JTAG 档**（通常是两位都 ON） |
| **跳线帽** | 底板跳 **PL 档**（例如 3–5、4–6 短接，跳线帽**竖插**同列相邻两针） |
| **下载器接口** | 插**专用 JTAG 座**（14-Pin），**不是** USB 串口口、**不是** USB SLAVE 口 |

⚠️ 尤其是第三条：**那两个 USB 口长得像、但都不能下载程序。**
底部板子往往**只有 JTAG 排针、没有板载 USB-JTAG**，必须外接下载器。

**怎么修**

按上面三条逐个确认。**先拿一个已知能跑的官方例程做冒烟测试**
（有些例程自带**已综合好的位流**，器件型号对得上就能直接烧，不必重新综合）
—— 先证明「链路是通的」，再去 debug 自己的设计。

**怎么预防**

**把这三条写进上板 checklist，每次上板照着走。**
这类问题的特征是**没有任何错误信息** —— 只能靠流程防。

**谁扛**：人（对着原理图 / 板子实物核对）

## 5. 复位极性相反

**现象**

接上板子行为完全不对；或者复位松开后设计不启动。

**原因**

**板子的复位信号极性与 RTL 的复位极性相反。**
实测：板载按键 `sys_rst_n` 是**低有效**，
而上游 RTL 的 `reset` 是**异步高有效**。

**怎么修**

顶层 wrapper 里取反。**不要改核内部的 RTL** ——
那会让核与「已经验证过的版本」不再逐字节相同。

**怎么预防**

**做顶层 wrapper 前，先把两边的极性列成一行对照**：

```
板子：sys_rst_n  低有效
RTL ：reset      异步高有效   →  wrapper 里取反
```

同类要核的还有：时钟频率、引脚约束的**电平标准**（如 LVCMOS33）。

**谁扛**：人

## 6. 引脚约束文件里同名信号定义了多次

**现象**

引脚约束到底用哪一组？两份来源（官方例程 XDC 与整板 XDC）说的不一样。

**原因**

整板 XDC 里同一个信号名可能**定义了多次**，是**互斥备选** ——
例如串口有三组（USB 转串口的、RS232 的、RS485 的），
对应**不同的物理接口**，只能启用一组。

**怎么修**

**两份独立来源交叉核对**，再把**不用的那几组注释掉**。
本项目实测两个来源一致：`sys_clk` / `sys_rst_n` / `uart_rxd` / `uart_txd`
（走 USB 转串口那一组），电平标准一致。

**怎么预防**

**不要只看一份 XDC 就下结论**，也不要以为「定义了多次 = 文件写错了」。

**谁扛**：人（对着自己板子的实际接口核对）

## 7. 位流掉电即失 / 别不小心覆盖出厂镜像

**现象**

断电再上电，设计不工作了，要重烧。

**原因**

**JTAG 配置是 SRAM 型的，掉电即失。**

**怎么修 / 怎么预防**

- 每次上电重烧；**把「重烧」写进演示前的 checklist**。
- ⚠️ 若要烧到 **QSPI Flash 做持久化，会覆盖出厂镜像**
  （有些板子的出厂镜像是有用的 Linux / demo 镜像）。
  **动手前先确认那个镜像能不能丢。**

**谁扛**：人

## 8. 工具版本：指南推荐的版本可能下载不到

**现象**

选题指南推荐某个较新的工具版本，但**下载不到**（账号权限 / 出口合规 / 官方下架）。
实际装的是一个更旧的版本。

**原因**

工具版本的可用性受**账号、地区、时间**影响，不是纯粹的技术选择。

**怎么修**

1. **实装版本照实写进报告**，不要含糊。
2. **把「可复现」的底牌放在不依赖该工具的地方** ——
   例如用开源仿真器（iverilog）跑完整验证链，让别人**不装商业工具也能验你的核心结论**。
3. 指南若允许用其他版本（通常附带「须在报告中说明并保证脚本可复现」），
   把这句话**原文引用进报告**，说明你们符合。

**怎么预防**

**别把整条验证链绑死在一个你控制不了版本的工具上。**
商用工具做「实现质量」，开源工具做「功能正确性」——
后者别人一定能复现。

**谁扛**：人
