# 提示词 ③：让 AI 讲懂它自己写的代码

**用途**：AI 写的代码**你能跑通 ≠ 你能讲清**。
这条提示词把「能跑」变成「能复述、能答辩、能在它坏的时候自己修」。

---

## 适用范围

**能用**：任何「AI 写了、你要对结果负责」的代码 —— 尤其是
**要答辩 / 要交接 / 要长期维护**的部分。

**不能用**：一次性脚本、注定要丢掉的探索代码 —— 对它们花这个时间不值。

⚠️ 前提：**你自己已经看过一遍代码**。完全不看就让 AI 解释，你无法判断它讲得对不对，
等于把「判断权」也交出去了。

---

## 怎么用

```
下面这段代码是你上一轮写的（可能你已经不记得了）：
<粘贴代码>

按顺序回答：

1. 逐行说明它在做什么。对每一处「初值 / 方向 / 掩码 / 位宽」，
   说明为什么是这个值，以及改成别的值会错成什么样。

2. 指出这段代码里「改一个字符就出错」的地方（脆弱点），
   并说明错了之后**现象是什么** —— 是报错，还是静默给出错误结果。

3. 用不懂 <领域> 的人能听懂的话，把整体在做什么讲一遍。

4. 出 3 个能检验我是否真懂了的问题。**先不要给答案。**
```

---

## 期望得到什么

- 一份「每一处常数都有理由」的逐行说明
- 一份**脆弱点清单 + 各自的失效现象**（这份最有价值）
- 一段人话版说明（可以直接放进报告或讲给队友）
- 3 道自测题

---

## 本项目的实例

**第 2 条问出来的东西直接救过一次**：AI 写的定点算术里有两处是**成对**的：

```js
const i16 = (x) => (x << 16) >> 16;      // 显式复现 C 的 int16_t 截断
const fqmul = (a, b) => montgomeryReduce(Math.imul(a, b));   // 32 位乘法，不用 *
```

它们对应的现象是「**静默**给出错误结果」—— 第 7 层数值全错，但不报任何错。
**换成 `a * b`（普通乘法）会溢出**，而溢出在调试输出里看不出来。
如果没有这份脆弱点清单，后来改这段代码的人（包括三个月后的自己）
很可能顺手「简化」掉 `Math.imul`，然后花半天找为什么最后一层对不上。

**第 3 条问出来的东西**：一段把「固定点算术、Montgomery 因子、位宽截断」
讲成人话的说明 —— 后来直接用在了报告的算法说明里。

**第 4 条问出来的东西的局限**：它出的是**代码层**的问题
（「这一行为什么用 `>>` 而不是 `/`」），**不会**问出架构层的取舍
（「为什么这个设计要做成可配置的」）。架构层的问题要单独问，见下面的失效条件。

---

## 失效条件

| 什么时候不管用 | 为什么 |
|---|---|
| 你自己没看过代码 | 无法判断它讲得对不对，等于把判断权也交出去了 |
| 想靠它补上架构层的理解 | 它默认只解释**这段代码**；「为什么这么设计、放弃了什么」要另开一次提问 |
| 代码是 AI 从别处「回忆」生成的 | 逐行说明会**同样自信地**讲错；先确认代码本身正确（见 `../checklists/ai-collaboration.md` 第 1 条） |
| 用它替代写注释 | 它输出的是**一次性理解**，不进代码库；关键脆弱点仍要写进代码注释 |

**补一条**：问架构层的「为什么」时，把**约束条件**一起给它
（器件多大、引脚多少、评分看什么），否则它会给你一个
「在真空里最优、在这个项目里不可行」的设计。
