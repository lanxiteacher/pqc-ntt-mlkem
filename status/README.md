# status/ —— 项目进度页

一页离线 HTML：`status/index.html`。**双击就能开**，不需要联网、不需要装东西、不需要
claude.ai 账号 —— 发给队友也是双击就能开。

它回答三个问题：

1. 这 8 周里三个人各自的活排在什么时候、走到哪了、**今天卡在谁身上**（主图，甘特图）；
2. 三个人此刻各自在干什么、下一步是什么；
3. **哪几份文档已经过期**（这一条是这页存在的主要理由）。

---

## 怎么重新生成

```bash
node status/gen_status.mjs            # 写出 status/index.html
node status/gen_status.mjs --check    # 只跑自检，不写文件
```

只要装了 node（A 本机 v24.15.0，C 本机 v24.19.0），**零依赖**，不用 `npm install`。
生成时会打印一行统计（三条线各最后一次提交、近 7 天提交数、文档取到日期几份）。

改完 `status.json` 或 `gen_status.mjs` 都要重跑一次，否则 `index.html` 是旧的。

## 数据从哪来：一半现抓，一半手写

| | 来源 | 谁维护 | 有哪些 |
|---|---|---|---|
| **AUTO** | 每次重跑时现抓 | 不用管，自动 | git 提交数／最后提交日／近 7 天提交数、分支与远端是否一致、各目录文件数与代码行数、各文档自称的更新日期、倒计时天数 |
| **MANUAL** | `status/status.json` | 人写 | 每条线的「正在做／下一步」、三个卡点、11 个里程碑、15 条待办、三个手写数字、**甘特图的 8 个周次 / 24 条排期 / 5 个交接点** |

**能自动抓的不要写进 `status.json`。** 写进去就会过期 —— 这页要治的就是过期。

`status.json` 里每条都必须带两个字段：

- `as_of`：这条是**几号**核的（人工判断有时间戳，才知道该不该重核）；
- `source`：这条**出处**在哪（文件 + 小节）。页面上每一格底部都把它印出来。

## 主图怎么看：甘特图

横轴是日期（W0–W7，共 8 周，从 2026-09-18 到 2026-11-07），纵轴是三块
（A · 硬件与上板 / B · 验证台与上位机 / C · 报告与演示），每块下面是自己那几条活。

**一根条上叠了两套独立的编码，故意的 —— 为了黑白打印也读得出来：**

- **颜色 = 哪一块**（蓝 A / 橙 B / 绿 C）。这三色过了色盲安全校验，色相是固定的，
  不会因为筛选而重新分配。
- **填充 = 什么状态**：实心＝已完成，半透明＋描边＝进行中，只有虚线轮廓＝计划中，
  **橙色虚线边框＝被卡住**（卡在谁身上，鼠标悬停能看，下面「欠账」一节也写了）。

另外三个记号：

- **图中那根竖直实线 = 今天**。线左边还没实心的条，就是已经落后了。
- **红色浅底的那几根 = 关键路径**（`critical: true`）。这几根不交，后面的动不了。
  现在有 5 根，正好连成 A 的 W1–W4 一条脊。
- **「交接点」那一行 = 里程碑**，标在它所属的那一周上；`key: true` 的那个（W4 · H6）画成
  红色虚线框，是全项目唯一那个硬交接口。

图上出现「⚠」的条，就是下面「欠账」里的某一条 —— 两处是同一份数据（`blockers[].bar`
指到 `gantt.bars` 的 `track + week`），不会各说各话。

窄屏（手机、半屏窗口）时图**自己横向滚动**，不挤扁、不换行 —— 它包在 `.gwrap` 里。

**改图就是改 `status.json` 的 `gantt` 段**：`weeks` 定义周次和起止日期，`bars` 一条活一行
（`track` / `week` / `label` / `state` / `critical` / `note` / `source`），`handoffs` 是交接点。
周次日期是照抄三份 `team/` 周计划表的，不是另起一套。

## 页面上那几个数字是什么意思

- **`35 天`**：距 `status.json` 里 `countdown.submission` 的天数。全页只有这一个英雄数字。
- **`4/11` 关键路径里程碑**：11 个里程碑里 `state` 为 `done` 的个数，分母就是
  `status.json` 的 `milestones` 条数。**改里程碑就改分母**，页面上会跟着变。
- **「数字一览」那 5 格**：4/11 关键路径 + 3 个手写数字（人写，带 `source` 和 `as_of`）
  + 三人提交总数（自动，现抓 `git log`）。每格底部都印着来源和核对日期。
- **文档新鲜度**（最后一节）：每份文档自称的更新日期距今多少天，分三档 ——
  `≤3 天` 新鲜、`4~7 天` 要留意、`>7 天` 过期（每条都带色点 + 图标 + 文字，不靠颜色单独表意）。
  取不到自称日期的，退而取该文件的最后一次 git 提交日，并在「取自」列标 `git`。
- **顶部那条橙色提示**：只盯一份文件 —— `logs/project_state.md`（每次开工读的第一份）。
  它超过 3 天变黄、超过 7 天变红。其余文档的过期情况在「文档新鲜度」表里。

## 目录里有什么

| 文件 | 是什么 |
|---|---|
| `index.html` | 生成物。**不要手改** —— 下次重跑就覆盖了。改 `gen_status.mjs` 或 `status.json`。 |
| `gen_status.mjs` | 生成器。零依赖，只用 node 内置模块。 |
| `status.json` | 唯一手写的文件：上一节表里 MANUAL 那一半全在这。 |
| `README.md` | 本文件。 |

`index.html` 是生成物，但仍然入库 —— 因为「发给队友／给评委看」这条路上，
对方可能没装 node。入库的那份永远能双击打开；要最新的，自己跑一遍生成器。

---

## 改待办 / 改进度的时候

1. 改 `status.json`（只改 MANUAL 那部分，`as_of` 改成今天）；
2. 跑 `node status/gen_status.mjs`；
3. 顺手把 `logs/` 入口记录也同步一下 —— 这页只能**显示**过期，不能替你更新。

待办表里 `state` 有四个值：`todo` / `doing` / `blocked` / `done`；
`owner` 只能是 `A` / `B` / `C`（页面上的筛选按钮就是按这个分的）。
