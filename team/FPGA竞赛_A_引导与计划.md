## 〇、30 秒背景

量子计算机迟早能破解现在的加密（RSA、ECC）。各国在推**后量子密码**，美国定的标准里做密钥交换的那个叫 **ML-KEM**。ML-KEM 里最耗时的一步叫 **NTT**（数论变换）。**我们要做一块 FPGA 硬件，让这一步跑得又快又省。**

关键：**我们已经有一份验证过是正确的 NTT 硬件基线，不用从零写。** "验证过"不是感觉，是拿美国国家标准的 1000 道官方考题验的。

---

## 一、你负责什么

把 NTT / INTT / 点乘三个数学运算变成能烧进 FPGA 的硬件，拿到资源与频率数字，并在板上真的跑起来。

**三个交付物：**

1. NTT / INTT / 点乘 三个硬件核（Verilog）
2. 综合 / 实现 / 时序报告 + 资源与频率数字（LUT / DSP / BRAM / 最高频率）
3. 引脚约束（XDC）+ bitstream + 板上跑通

**你的工位**：板子在你这里，Vivado 也装在你这里。原因是物理的——bitstream 由 Vivado 生成、也由 Vivado 下载，而板子只有一块、只能插在一台机器上。上板失败的原因（时序不收敛、资源超了、数据不对）都要退回来改 RTL，工位和 RTL 在一起，返工不用跨人描述"时序违例长什么样"。

**你的工位同时是本组的单点。** 第六节讲怎么控制这个风险。

## 六、卡住了怎么办

| 卡在哪 | 怎么办 |
|---|---|
| Vivado 装不上 | 先别停 RTL。仿真的活照做，Vivado 后台重下 |
| 板子不通 | 先跑官方 `19_uart_loopback` 例程确认是工具链问题还是你的设计问题 |
| 时序不收敛 | 降折叠度 / 加流水级 / 降目标频率。先出一个能跑的低频版本 |
| INTT 对不上 | 回 `refsim/run_ntt_layers.sh` 看层序表。注意 `poly_ntt()` 比裸 `ntt()` **多一步约减**，两者输出不相等 |
| 上板数据不对 | **先在仿真里复现**。这是纪律，见下 |

**降级顺序**：先砍功能深度，后砍文档。可以不做"折叠度可配置"只交固定版本，但不能交不出东西。

## 七、你的红线

**仿真能抓到的问题，不要留到板上去抓。**

板级调试每一轮都要重新综合、实现、下载，一轮十几分钟起步，而且现象难描述——"串口没数据"可能是引脚、可能是时序、可能是协议、可能是上位机。四个原因混在一起，很难定位。

RTL 的错先在 `refsim/` 里验干净。板子只用来确认"综合出来确实能跑"，不是用来 debug 逻辑的。

这条做到了，你的负载就是可控的；做不到，你会同时被 RTL 和板子两边拉扯。
