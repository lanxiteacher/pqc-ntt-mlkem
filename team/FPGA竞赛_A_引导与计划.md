## 〇、30 秒背景

量子计算机迟早能破解现在的加密（RSA、ECC）。各国在推**后量子密码**，
美国定的标准里做密钥交换的那个叫 **ML-KEM**。ML-KEM 里最耗时的一步叫 **NTT**。
**我们要做一块 FPGA 硬件，让这一步跑得又快又省。**

拿 **256 个数字**，按固定规则重排组合 **7 遍**：每一遍把所有数字两两配对，
每对做一次「一加一减、再乘个常数」的动作（这个动作叫**蝶形**）。这就是 NTT。

**关键：我们不是从零开始写。** 网上有一份别人写好、
并且已经用官方考题验证过是正确的硬件设计，我们叫它**基线**，放在
`research/ref_rtl/kyber-polmul-hw/pe1/`。你的工作是**改造它**，不是重写它。

---

## 一、你负责什么

把 NTT／INTT／点乘这三个数学运算变成能烧进芯片的电路，
拿到「占多少资源、能跑多快」的数字，并在真板子上跑起来。

**三个交付物：**

1. NTT／INTT／点乘 三个硬件模块（用 Verilog 写）
2. 综合 / 实现 / 时序报告 + 资源与频率数字（用了多少 LUT／DSP／BRAM、最高能跑多快）
3. 引脚约束（XDC）+ `.bit` 文件 + 板上真的跑通

**你的工位**：板子在你这里，Vivado 也装在你这里。原因是物理的——
`.bit` 文件由 Vivado 生成、也由 Vivado 下载，而板子只有一块、只能插在一台机器上。
上板失败的原因（时序不收敛、资源超了、数据不对）都要退回来改 RTL，
工位和 RTL 在一起，返工不用跨人描述「时序违例长什么样」。

**你的工位同时是全组的单点。** 第六节讲怎么控制这个风险。

### 环境两件事，每次开工先做

**1. iverilog 不在 PATH 里。** 每次开新终端先敲：

```bash
export PATH="/c/iverilog/bin:$PATH"
```

**2. 所有数据文件用 LF 行尾。** 我们踩过这个坑——Windows 默认写出 CRLF，
256 个数字明明全对，`diff` 却报「256 行全不同」，白查半天。
在 Python 里写文件用 `"wb"` 不用 `"w"`。

## 五、交接点

**交接的意思是**：你手上的东西，什么时候必须变成队友能用的东西。
拖着不交，队友不会来催，他们只会卡住或者猜——两种情况都比交接本身贵得多。

### 你要交出去的

| | |
|---|---|
| **交什么** | 端口名、方向、位宽；以及时序——什么时候给开始信号（`start`）、几拍之后出完成信号（`done`）、结果什么时候有效、连续两次运算之间要不要间隔 |

## 六、卡住了怎么办

| 卡在哪 | 怎么办 |
|---|---|
| Vivado 出问题 | 先别停 RTL。仿真的活照做，Vivado 那边慢慢查 |
| 板子不通 | 先跑官方 `19_uart_loopback` 例程，确认是工具链问题还是你的设计问题 |
| 时序不收敛 | 降折叠度／加流水级／降目标频率。**先出一个能跑的低频版本** |
| INTT 对不上 | 回 `refsim/run_ntt_layers.sh` 看层序表。注意 `poly_ntt()` 比裸 `ntt()` **多一步约减**，两者输出**不相等** |
| 上板数据不对 | **先在仿真里复现**。这是纪律，见下 |

**降级顺序**：先砍功能深度，后砍文档。可以不做「折叠度可配置」只交固定版本，
但不能交不出东西。

## 七、你的红线

**仿真能抓到的问题，不要留到板上去抓。**

板级调试每一轮都要重新综合、实现、下载，一轮十几分钟起步，
而且现象难描述——「串口没数据」可能是引脚、可能是时序、可能是协议、可能是上位机。
四个原因混在一起，很难定位。

RTL 的错先在 `refsim/` 里验干净。板子只用来确认「综合出来确实能跑」，
**不是用来 debug 逻辑的**。

这条做到了，你的负载就是可控的；做不到，你会同时被 RTL 和板子两边拉扯。
