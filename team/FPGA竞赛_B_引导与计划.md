## 〇、30 秒背景

量子计算机迟早能破解现在的加密（RSA、ECC）。各国在推**后量子密码**，
美国定的标准里做密钥交换的那个叫 **ML-KEM**。ML-KEM 里最耗时的一步叫 **NTT**。
**我们要做一块 FPGA 硬件，让这一步跑得又快又省。**

拿 **256 个数字**，按固定规则重排组合 **7 遍**：每一遍把所有数字两两配对，
每对做一次「一加一减、再乘个常数」的动作（这个动作叫**蝶形**）。这就是 NTT。

**关键：我们有一份验证过是正确的基线，不用从零写。**
而「验证过」这三个字，是你这块要负责守住的。

## 一、你负责什么

**证明硬件算得对，并且让别人也能一键复现这个证明。**

**四个交付物：**

1. 扩展后的验证台（覆盖 NTT／INTT／点乘三个运算）
2. PC 上位机程序（串口喂数据、收回结果、自动比对）
3. 验证数据（考了多少条、对了多少条、数据够不够五花八门、波形截图）
4. 开源仓库（别人 clone 下来能跑通）

### 三个词先说清楚

- **验证台**：一套自动测试。一条命令跑完，它自己喂数据给电路、自己跟标准答案比，
  最后告诉你「4096 个数字全对」。
- **上位机**：你写的一个电脑程序。它通过串口线把数据发给板子、
  把结果收回来、自动跟标准答案比对。板子只是算得快，**发数据和判对错都是上位机的事**。
- **对拍**：我们的硬件算一遍、C 语言写的标准版本算一遍，两份结果**逐位比较**。
  全一样才算过。

**你的位置**：全组唯一的「正确性」出口。别的队伍只能写「仿真通过」，
我们能写「用官方 1000 道考题验过，4096 个数字逐位一致」——
这是可复算的硬证据，对应评分表里「功能正确性 20 分」。

**你全程不需要板子。** 串口协议的两端——电脑发什么、板子回什么——
可以先在仿真里全部跑通（在测试台里接一个「假串口」）。
等真上板时，变量就只剩「硬件对不对」一个，而不是「协议 + 硬件」两个一起猜。
**你的进度因此不被 A 的板子卡住。**

### 环境三件事，每次开工先做

**1. iverilog 不在 PATH 里。** 每次开新终端先敲：

```bash
export PATH="/c/iverilog/bin:$PATH"
```

**2. 所有数据文件用 LF 行尾。** 我们踩过——Windows 默认写出 CRLF，
256 个数字明明全对，`diff` 却报「256 行全不同」。写文件用 `"wb"` 不用 `"w"`。

**3. 无界等待会让仿真永久挂死。** 作者的原始测试台用了 `while (done == 1'b0)`。
单次跑没事，套进 16 轮循环后任何一轮异常都会**卡住而不是报错**。
自己写的时候加计数护栏（最多等多少拍就报错退出）。

**⚠️ 改 RTL 只在副本上改。** `refsim/pe1/` 是 `ref_rtl/` 的复制品，原始目录保持原样。

## 六、卡住了怎么办

| 卡在哪 | 怎么办 |
|---|---|
| 对拍不通过 | 先确认**比的是哪一个**：`poly_ntt()` 比裸 `ntt()` **多一步约减**，两者输出**不相等**。比错了会一直假报失败 |
| `diff` 报「全部不同」 | 先怀疑**行尾**，别急着怀疑数值 |
| 仿真挂死不动 | 检查有没有无界 `while (done == 0)`，加计数护栏 |
| 拿不到 A 的端口说明 | 主动要。同时可以先照 `refsim/pe1/` 里已有模块的时序风格写个草稿 |
| 板子连不上 | 那是 A 的工位问题，别自己死磕，直接找他 |
| 上位机对仿真跑不通 | **别急着上板。仿真里都跑不通，上板只会更难查** |

**降级顺序**：上位机做不完就用仿真波形截图代替串口实测；
但**验证数据本身不能省**——它是 20 分的载体。

## 七、你的红线

**「通过」必须能被别人复算。**

每次报告「通过」，都要能回答：用了多少组数据？多少条官方考题？
覆盖了多少个不同的输入值？换个人按 README 走一遍，能不能得到同样结果？

**特别注意「非退化」**：如果数据全是 0、全是一个常数、或者只有几个不同的值，
那「全中」很可能是**巧合**而不是正确。灌数据前先统计一下有多少个不同的值
——我们现有的数据是 4096 个数里 2355 个不同值。你的新数据至少要达到这个量级。

这一步做了，「20 分基本能拿满」才站得住；不做，「通过」两个字经不起问。
