## 〇、30 秒背景

量子计算机迟早能破解现在的加密（RSA、ECC）。各国在推**后量子密码**，美国定的标准里做密钥交换的那个叫 **ML-KEM**。ML-KEM 里最耗时的一步叫 **NTT**（数论变换）。**我们要做一块 FPGA 硬件，让这一步跑得又快又省。**

关键：**我们已经有一份验证过是正确的 NTT 硬件基线，不用从零写。** 而"验证过"这三个字，是你这块要负责守住的。

---

## 一、你负责什么

**证明硬件算得对，并且让别人也能一键复现这个证明。**

**四个交付物：**

1. 扩展后的验证台（覆盖 NTT / INTT / 点乘三个运算）
2. PC 上位机程序（串口喂数据、收回结果、自动比对）
3. 验证数据（KAT 通过率、对拍系数个数、非退化性统计、波形截图）
4. 开源仓库（别人 clone 下来能跑通）

**你的位置**：全组唯一的"正确性"出口。别的队伍只能写"仿真通过"，我们能写"用 FIPS 203 标准的 1000 道考题验过，4096 个系数逐比特一致"——这是可复算的硬证据，对应评分表里"功能正确性 20 分"。

**你全程不需要板子。** 串口协议的两端——PC 发什么、板子回什么——可以先在仿真里全部跑通（testbench 里接一个 UART 模型）。等真上板时，变量就只剩"硬件对不对"一个，而不是"协议 + 硬件"两个一起猜。你的进度因此不被 A 的板子卡住。

**⚠️ iverilog 在 `/c/iverilog/bin`，不在 PATH 里。** 每次开新终端先跑：

```bash
export PATH="/c/iverilog/bin:$PATH"
```

**⚠️ 数据文件统一用 LF 行尾。** 我们踩过：Windows 默认写出 CRLF，256 个系数明明全对，`diff` 却报"256 行全不同"。写文件用 `"wb"` 不用 `"w"`。

**⚠️ 无界等待会让仿真永久挂死。** 作者的原始 testbench 用了 `while (done == 1'b0)`。单次跑没事，套进 16 轮循环后任何一轮异常都会卡住而不是报错。自己写的时候加计数护栏。

**⚠️ 改 RTL 只在副本上改。** `refsim/pe1/` 是 `ref_rtl/` 的复制品，原始目录保持原样。

## 六、卡住了怎么办

| 卡在哪 | 怎么办 |
|---|---|
| 对拍不通过 | 先确认**比的是哪一个**：`poly_ntt()` 比裸 `ntt()` 多一步约减，两者输出**不相等**。比错了会一直假报失败 |
| 行尾 / 格式问题 | 统一 LF。`diff` 报"全部不同"时先怀疑行尾，别急着怀疑数值 |
| 仿真挂死 | 检查有没有无界 `while (done == 0)`，加计数护栏 |
| 拿不到 A 的端口说明 | 主动要。同时可以先按 `refsim/pe1/` 里已有模块的时序风格写个草稿 |
| 板子连不上 | 那是 A 的工位问题，别自己死磕，直接找他 |
| 上位机对仿真跑不通 | 别急着上板。仿真里都跑不通，上板只会更难查 |

**降级顺序**：上位机做不完就用仿真波形截图代替串口实测；但**验证数据本身不能省**——它是 20 分的载体。

## 七、你的红线

**"通过"必须能被别人复算。**

每次报告"通过"，都要能回答：用了多少组向量？多少条 KAT？覆盖了多少个不同的输入值？换个人按 README 走一遍，能不能得到同样结果？

**特别注意"非退化"**：如果向量全是 0、全是一个常数、或者只有几个不同的值，那"全中"很可能是巧合而不是正确。灌数据前先统计一下有多少个不同的值——我们现有的向量是 4096 个系数里 2355 个不同值、覆盖 0..3327 全域。你的新向量至少要达到这个量级。

这一步做了，"20 分基本能拿满"才站得住；不做，"通过"两个字经不起问。
