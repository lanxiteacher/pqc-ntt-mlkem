## 〇、一句话说清我们在做什么

量子计算机迟早能破解现在的加密（RSA、ECC）。各国在推**后量子密码**，美国定的标准里做密钥交换的那个叫 **ML-KEM**。

ML-KEM 里最耗时的一步叫 **NTT**（数论变换），是个纯数学变换。**我们要做一块 FPGA 硬件，让这一步跑得又快又省。**

**关键现状：我们已经有一份"确认正确"的硬件基线了。** 不用从零写。这不是"我们觉得它对"，是拿美国国家标准的 1000 道官方考题验过的（细节见第三节）。

**所以分工的铁律是：不能三个人全扑在"把东西做出来"上。** 必须固定有人守过程分。零基础队伍最容易犯的错，就是三个人一起埋头调 bug，最后东西勉强跑起来了，报告和视频烂得没法看，白丢 30 分。

## 三、三个人分别干什么

> **分工的判据是"阻不阻塞"**：A、B 的任务在关键路径上，一个卡住全线停摆；
> C 的任务不依赖板子和 Vivado，可并行推进。

> **关于"工位"**：bitstream 由 Vivado 生成、也由 Vivado 下载到板子，而板子只有一块、
> 只能插在一台机器上。所以"装了 Vivado 的机器 + 板子"是**一个物理工位**，只能有一个主责人：
> **A**（板子在 A 手里，Vivado 也就装在那台机器上）。
> 上板失败的原因（时序不收敛、资源超了、数据不对）都要退回去改 RTL，
> 工位和 RTL 在一起，返工不用跨人描述。

### 🅰️ A —— 算法核 RTL + 综合实现 + 上板

**一句话**：把 NTT / INTT / 点乘三个数学运算变成能烧进 FPGA 的硬件，拿到资源与频率数字，并在板上真的跑起来。

**起点**：`research/ref_rtl/kyber-polmul-hw/pe1/` —— 一份开源的现成 NTT 硬件，
**已经验证过是对的**，直接拿它改造，别从零写。

**要做的事**：
1. ~~装 Vivado~~ ✅ **2026-09-19 已完成** —— **Vivado ML Standard 2020.2**
   （`E:\Xilinx\Vivado\2020.2`，Cable Drivers 已勾，占用 42.25 GB）
   - 装完先跑通官方 `19_uart_loopback` 例程，确认工具链和板子都可用
2. 读懂 `pe1/` 的蝶形单元和地址生成器（配套文档在《PQC-NTT 技术资料汇编》第一部分）
3. 补出 **INTT** 和 **点乘** 两条通路（向量已备好，就等接进去）
4. 在 Vivado 里综合、实现、收敛时序，产出 LUT / DSP / BRAM 占用和最高频率
5. 写一个"折叠度可配置"的版本 —— 这是我们**创新性 30 分**的主要卖点
6. **上板**：写引脚约束（XDC）→ 下载 bitstream → 和 B 的上位机闭环跑通

**怎么算做完了**：三个核在仿真里跑过对拍、综合出资源与频率数字、并且在板上真的跑起来。

**一条能省很多时间的纪律**：**仿真能抓到的问题，不要留到板上去抓。**
板级调试每一轮都要重新综合、实现、下载，一轮十几分钟起步，而且现象难描述
（"串口没数据"可能是引脚、可能是时序、可能是协议、可能是上位机）。
RTL 的错先在 `refsim/` 里验干净 —— 这套验证台存在的意义就是这个。

**现在就能开工**：仿真器（iverilog）已装好，RTL 可以先写、先验；Vivado 一边下载一边装。

### 🅱️ B —— 验证 + 上位机（守"功能正确性 20 分"）

**一句话**：证明硬件算得对，并且让别人也能一键复现这个证明。

**起点**：`refsim/` —— 一套已经跑通的验证台，一条命令跑完全流程。
还有 `research/mlkem_kat/` —— 官方考题环境（1000 条全过）。

**要做的事**：
1. **把现有验证台扩到 INTT 和点乘**（A 写完一块，就接一块进验证台）
2. 写 PC 端上位机程序：通过串口把数据喂给板子、收回来、自动和标准答案比对
3. **上位机先对着仿真调**：把 UART 收发灌进 testbench，在真板子之前先跑通协议
4. 和 A 约一次**板级联调**（1–2 天），把上位机和真板子接通
5. 整理验证报告**数据**（KAT 通过率、对拍系数个数、波形截图）→ 交给 C 成文
6. 建开源仓库，保证"别人 clone 下来能复现"（对应"文档与可复现 15 分"）

**评分表上我们最有把握的一项**：别的队伍只能写"仿真通过"，我们能写
"用 FIPS 203 标准的 1000 道考题验过，4096 个系数逐比特一致"——
这是可复算的硬证据，20 分的"功能正确性"基本能拿满。

**为什么 B 全程不需要板子**：串口协议的两端——PC 发什么、板子回什么——可以先在
仿真里全部跑通（testbench 里接一个 UART 模型）。等真上板时，变量就只剩"硬件对不对"
一个，而不是"协议 + 硬件"两个一起猜。B 的进度因此不受板子影响。

**现在就能开工**：验证台和上位机都不用等 Vivado。

## 四、衔接约定（不做这个，三个人会互相等）

| 谁 ↔ 谁 | 约定什么 |
|---|---|
| A → B | 每写完一个模块，给 B 一份**端口说明**（输入输出位宽、时序） |
| B → A | 黄金向量文件格式：**每行一个十六进制系数**，共 256 行 |
| A → B | 顶层端口清单：`clk`(50MHz) / `rst` / `uart_rx` / `uart_tx`，以及时钟复用极性 |
| A ↔ B | 串口协议：波特率（建议 115200）、数据帧格式、命令字 —— **两边各实现一端** |
| A、B → C | 每完成一小步，把**截图/录屏 + 一句话说明**丢进素材目录，别攒 |
| A → C | 综合/实现报告（`.rpt` 文件）+ 波形截图 → C 做进报告和演示页 |
| C → A、B | 演示页需要什么数据格式，提前说，别等到剪视频时才提 |

**⚠️ 一条踩过的坑，写进约定里**：所有交给仿真的数据文件，**统一用 LF 行尾**。
我们踩过——Windows 默认写出 CRLF，导致 256 个数明明全对，diff 却报"256 行全不同"，
白查半天。

## 六、风险与降级（做不完怎么办）

本届的底线是**"11/04 18:00 必须有东西能交"**（10-04 订正，原写 11/7 —— 那是上一届的日期）。所以每块都准备一条退路：

| 风险 | 降级方案 | 主责 |
|---|---|---|
| Vivado 装不上 / 板子不通 | **纯仿真演示 + 波形动画**，报告里说明环境问题；验证报告照样是完整的 | A |
| INTT 调不出来 | 只交 NTT 单核，把验证做扎实（正确性 20 分照样能拿） | A |
| 上位机写不完 | 用仿真波形截图代替串口实测 | B |
| **A 被上板卡住、连累 RTL 停摆** | **B 那条线不受板子影响，照常推进**；上板降级为"跑通官方例程 + 波形截图" | A + B |
| 时间不够 | **优先保报告 + 视频 + 开源仓库**，这三样是过程分的载体 | C |

**降级的顺序原则**：**先砍功能深度，后砍文档。** 功能砍了只丢单项分，文档烂了丢 30 分。
（具体说：可以不做"折叠度可配置"只交固定版本，但不能不写报告。）

**⚠️ 已知的单点风险**：工位和 RTL 都在 A 身上。缓解办法只有一条 ——
**别把不确定性带到板上**。RTL 在仿真里就该验干净，板子只用来确认"综合出来确实能跑"，
而不是用来 debug 逻辑。这条做到了，A 的负载就是可控的。
